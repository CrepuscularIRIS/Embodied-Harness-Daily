### 2501.04268 v1 — RoboPro: Video Instructed Policy Code Generation for Robotic Manipulation
- **OPERATION**: synthesize (image, instruction, API-code) triples from robot videos (Gemini-1.5-Flash plans from 16 key frames, DeepSeek-Coder-V2 translates the plan into code for a fixed API) and SFT a compact code VLM on them.
- **INFO ACCESS**: Teachers see video frames and API docs. No program is executed or success-filtered (inferred, Sec III-B). The student (SigLIP + CodeQwen-1.5-7B) is trained and sees wrist image, instruction and API definitions.
- **CLUSTER**: new **(i) unverified video-to-code SFT corpus for a code VLM**; near K501 but no harness teacher or success filter.
- **WORKS**: RLBench avg 42.7 vs GPT-4o 31.1, CaP 23.6, PerAct 43.6 (Table I). LIBERO 52.4 vs 35.0 (Table II). Unseen-skill APIs 44.0 vs 25.3 (Table III). Real 72.5 vs 60.0 (Table IV). No Video2Code: 0.4 / 7.0 (Table V).
- **FAILS**: 25 episodes/task, one run; 10 real trials/task. The ablation drops all code SFT, not the video source specifically (inferred).
- **COUNTER**: Ties GPT-4o on Stack Cups (4) and Put in Board (12). Real-world Distinct Base 70 vs GPT-4o 80. API refactoring drops Sweep Dirt from 48 to 16 (Table I).

### 2502.19135 v2 — PLANTOR: LLMs + symbolic reasoning for multi-robot temporal planning via Prolog KBs
- **OPERATION**: have an LLM write a two-level Prolog KB (high-level actions, low-level actions, mappings). Check it with Prolog consistency predicates and feed failures back to the LLM up to 3 times. Then plan by BFS, extract a partial order, schedule with OR-Tools and emit a behaviour tree.
- **INFO ACCESS**: Frozen LLMs at temperature 0 with few-shot Blocks World/AGV examples. A human confirms validation and hand-fixes KBs that do not plan (Sec 5, 7.3.2).
- **CLUSTER**: **(a)**.
- **WORKS**: Opus 4.6 and GPT 5.2 classify all 16 validation queries correctly (Table 1). In the high-level KBs, 54 of 78 required edits fall in the action set, and Opus needs 1 edit across 12 instances (Table 2). 27 of 72 low-level KBs need no edit (Table 3).
- **FAILS**: No end-to-end success without human repair. The repair loop is not ablated. Mixtral yields no feasible KB. Two-level reuse is not evaluated (Sec 8.1). The real robot is a demo only.
- **COUNTER**: Mixtral accepts all three deliberately invalid Blocks World specs (Table 1). An LLM-based validation gate can be sycophantic.

### 2502.19417 v2 — Hi Robot: open-ended instruction following with hierarchical VLA models
- **OPERATION**: fine-tune a high-level VLM to map (images, open prompt or user interjection) to an atomic language command plus an optional spoken reply. A trained π0 VLA executes the command. The high level re-runs every 1 s or on each user utterance.
- **INFO ACCESS**: Both levels are trained from PaliGemma-3B. High-level data: human-segmented skill labels plus prompts and interjections a large VLM back-generates from (image, skill label). The levels do not know each other's capabilities (Sec 6).
- **CLUSTER**: **(b)**.
- **WORKS**: Results are only in Figs 5–8, with no numbers in the text. The text says instruction accuracy and task progress are higher than the GPT-4o high level and the flat π0. Ablations removing synthetic data, and a flat model trained with synthetic data, both lose (Sec 5.3–5.4). 20 blind-evaluated trials per task per method (Sec 5.2).
- **FAILS**: Numbers not checkable from text. GPT-4o gets ranked skill labels but no fine-tuning. With an expert-human high level the low level is near flawless, so the bottleneck is reasoning.
- **COUNTER**: none in the text.

### 2503.01700 v2 — Code-as-Symbolic-Planner
- **OPERATION**: have one frozen LLM play three roles: TaskLLM writes solver/search code, CheckLLM writes and runs checker code on the answer, and SteerLLM re-guides. A rule-based checker scores symbolic complexity. The loop runs at most 3 rounds, after which the answer is forced.
- **INFO ACCESS**: Full environment state is given as text (Sec III). Nothing is trained. There are no few-shot examples.
- **CLUSTER**: **(a)**, variant where the LLM writes the solver instead of calling a fixed one.
- **WORKS**: GPT-4o avg 52.3 vs Code Interpreter 34.3 and Code Answer 30.5. Without the complexity checker 41.3, without CheckLLM 42.7 (Table I). Claude 63.9 vs 28.8 and Mistral 46.0 vs 26.9 (Table II). 3D BoxNet with six robots: 95% vs 35% over 20 runs (Table III).
- **FAILS**: Planning is open-loop from text. Code over 50 s times out. Gains plateau after 3 rounds (Fig 6). The checker is LLM-written.
- **COUNTER**: Claude BoxNet 52.2 is below Only-Question 67.1 (Table II). Code Interpreter beats it on BoxNet (76.7 vs 74.2) and BoxLift (19.6 vs 17.6) (Table I).

### 2503.02465 v2 — UAV-VLRR: Vision-Language informed NMPC for UAV search and rescue
- **OPERATION**: GPT-4o extracts target and obstacle names, and Molmo-7B (4-bit) points at them in one aerial image. The pixels are scaled to metres from camera height and FoV. A point-to-point NMPC with an obstacle penalty flies the route.
- **INFO ACCESS**: All models are frozen. One image per mission. No feasibility check or reselection.
- **CLUSTER**: **— (UAV systems)**: K103 without the check/reselect loop.
- **WORKS**: Point errors are 0–23 cm (Tables I–II). Mission time 28/30 s vs off-the-shelf autopilot 40/48 s vs human 57/72 s (Table III).
- **FAILS**: Two scenes, one command, no repeats reported (inferred). The autopilot run also uses the multimodal points (Sec V-B), so the speed gain belongs to the NMPC, not the VLM. Static indoor arena.
- **COUNTER**: none.

### 2503.04280 v4 — ARCHIE: autonomous RL for real-world manipulation with LLMs
- **OPERATION**: GPT-4 writes dense shaping reward code plus success and failure classifiers inside a fixed reward form (terminal bonus = 10·T·max(Σ bonuses, 1)). SAC trains in simulation in one shot, with no reward reflection.
- **INFO ACCESS**: GPT-4 sees the base environment class code, the API docs and a user description that states the success/failure geometry. The SAC agent sees privileged simulator poses.
- **CLUSTER**: **(e)**, one-shot variant with no revision from traces.
- **WORKS**: Results are in Figs 2–4 only. The text says ARCHIE solves all benchmark tasks where Eureka step-0 rewards are inconsistent. GPT-4 code policies solve none of the 10 tasks, and distance rewards solve few (Sec V-B).
- **FAILS**: No numbers in the text. 3 seeds per task. Baselines are Eureka step-0 and a hand-written distance reward, not full Eureka. The authors report instability on some tasks. The real robot is shown qualitatively.
- **COUNTER**: They argue that formalizing the reward replaces iterative revision, which runs against the "revise from traces" half of (e). Full Eureka is never compared.

### 2503.08302 v1 — General-purpose aerial intelligent agents empowered by LLMs
- **OPERATION**: Stage 1: an onboard LLM (DeepSeek-R1 14B) drafts the mission plan, and a human approves it or reruns. Stage 2: files holding pose and obstacles, VLM scene text, field geodesy and a fixed action set fill a template. The LLM picks an action plus waypoints, which go to the flight controller.
- **INFO ACCESS**: Frozen Llama 3.2 Vision 11B. The LLM sees text only.
- **CLUSTER**: **— (UAV systems) / (d)**. This is a system paper.
- **WORKS**: 14B inference at 5–6 tokens/s and about 220 W (Sec IV). Plans for the four applications are shown qualitatively (Sec V-B), and VLM scene descriptions are shown (Fig 5).
- **FAILS**: No success metric. The LLM motion-planner stage is never flight-tested ("will further validate … through real flight tests", Sec VI). The stage-1 plans are human-gated.
- **COUNTER**: none.

### 2503.10069 v2 — SmartWay: waypoint prediction and backtracking for zero-shot VLN-CE
- **OPERATION**: a trained waypoint predictor (DINOv2, masked cross-attention, depth-derived occupancy loss) proposes candidate waypoints. Frozen GPT-4o picks one from candidate images with RAM tags, history and its own carried multi-step plan, and can choose an extra "move back to last position" option.
- **INFO ACCESS**: The predictor is trained. The navigator is zero-shot.
- **CLUSTER**: new **(j) trained candidate proposer + frozen MLLM selector with an undo action**. It is near K104(b), but the candidates change every step.
- **WORKS**: R2R-CE (100 episodes) SR 29 / SPL 22.46 / OSR 51 vs Open-Nav-GPT4 19 / 16.10 / 23 (Table I). Waypoints in open space 87.26% vs 79.86% (Table IV). Real robot SR 36 with backtrack vs 24 without vs RecBERT 20 (Table II).
- **FAILS**: One 100-episode run. Supervised methods reach 52–60 SR. Undo is a single step. The collision figure in the text (0.044) does not match Table V.
- **COUNTER**: NE 7.01 is worse than Open-Nav-GPT4's 6.70, and the full system's NE is worse than predictor-only (7.01 vs 6.73) (Tables I, V).

### 2503.12533 v2 — Being-0: humanoid agent with VLMs and modular skills
- **OPERATION**: frozen GPT-4o reasons, detects skill success and names the next skill. A trained lightweight VLM "Connector" grounds that into skill commands: it runs closed-loop navigation from a bbox plus stereo depth and adjusts the robot's pose before manipulation. The skills are RL joystick locomotion and ACT manipulation.
- **INFO ACCESS**: The FM is frozen. The Connector (VideoLLaMA2) is trained on annotated first-person navigation images, and all skills are trained.
- **CLUSTER**: **(b)**, variant with a frozen top over a trained middle layer.
- **WORKS**: Without vs with Connector: Fetch-bottle 0.00→0.90, Deliver-basket 0.00→0.80, Prepare-coffee 0.00→0.75, Deliver-coffee 0.33→0.87 (Table 1). Navigation 2.3→9.6 cm/s, 0/5→5/5 (Table 4). Pose adjustment: Grasp-coffee 1/5→4/5 (Table 2).
- **FAILS**: Ablations use 5 trials. One office. Table 1 trial counts are not given in the text.
- **COUNTER**: Make-coffee is 0.90 with or without the Connector. Place-basket is 4/5 without adjustment vs 3/5 with it.

### 2503.22122 v2 — REMAC: self-reflective, self-evolving multi-agent collaboration
- **OPERATION**: a VLM pre-condition check gates each subtask; failure triggers a replan, logged as a reflection. A post-condition check triggers a retry. Reflections from earlier iterations of the same task feed the next initial plan. Once one robot succeeds, a second takes over the pre-conditions.
- **INFO ACCESS**: Frozen DeepSeek-R1 plans and reflects; frozen GPT-4o checks. Scene item list given. Low-level policies pretrained.
- **CLUSTER**: **fits K302 good**, plus a weak K201 (the gate is a VLM, not a cheap checker), plus (c).
- **WORKS**: Task success, BASE→CC→RE (Table 1): OpenCabinet 0→20→30, Microwave 10→40→50, Defrost 0→20→50, Stove 10→50→50. Real robot Phase 4 success: 0 / 10 / 25% for BASE / CC / REMAC over 20 runs (Table 3). Reflection success Grok3 82.5% vs GPT-4o 12.5% (Table 2).
- **FAILS**: 10 initializations per setting, own benchmark, iteration count not stated. It evolves on the evaluation tasks themselves (inferred).
- **COUNTER**: Adding the second robot lowers Defrost success 50→40 and OpenCabinet subtask completion 71.67→67.50. Reflection gives no gain on Stove (50 vs 50).
