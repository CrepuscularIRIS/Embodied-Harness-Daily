### 2603.04466 v1 — Act-Observe-Rewrite (AOR)
- **OPERATION**: between episodes, a coding agent reads key frames, phase logs and the controller source, diagnoses the failure and emits a new Python controller class; sandbox-compile, clamp actions, fall back on error.
- **INFO ACCESS**: Claude Code (frozen) sees 256×256 RGB-D key frames, structured outcomes, its own code; no ground-truth object pose in the controller; nothing trained.
- **CLUSTER**: (e) LLM writes controller code and revises it from trial traces.
- **WORKS**: Table 3: Lift 100% (3 calls), PickPlaceCan 100% (2 calls; 20/20 repeats, §6.2), Stack 91% (20 calls). Table 2: Stack 0% (v0–v6) → 33% after y-flip fix → 91% at v20.
- **FAILS**: no baseline at all; trial counts behind 91% unstated; search and evaluation on the same task instances (no held-out split); 3 robosuite tasks, sim only; Stack residual contact failure never fixed (§6.2).
- **COUNTER**: Codex (GPT 5.3, high) solved none of the three tasks with the same budget (§6.1), so the gain belongs to the agent, not the loop.

### 2602.19983 v2 — CORE (contextual safety reasoning + CBF)
- **OPERATION**: per frame, a VLM emits safe/unsafe predicates (operator + class); SAM3 segments them, depth back-projects into a count grid thresholded to a signed-distance barrier; a CBF-QP minimally edits the nominal command.
- **INFO ACCESS**: Gemma 3 27B (4-bit), SAM3 frozen; RGB-D + odometry; no maps or specs in advance.
- **CLUSTER**: new (i) "VLM-inferred constraints compiled into a runtime safety filter on a nominal controller". Not K201: it does not gate model proposals.
- **WORKS**: Table I (60 sim evals): 95.0% vs No Context 55.0%, Geometric 50.0%, Oracle 98.3%; unsafe tasks 93.3% vs 16.6%. Table IV (Spot): 86.6% vs 50.0%. Table III: removing CoT drops it to 61/77 from 91/85.
- **FAILS**: author-designed adversarial goals; 4 tasks × 3 envs × 5 runs; 4.1 s latency; guarantee needs Assumption 1 (unsafe region is seen before the robot enters it); the main hardware failure is grounding (9.0%).
- **COUNTER**: Qwen3-VL 30B with reasoning scores below Gemma 27B (75% vs 88%, Table II). The safety-logic prompt barely matters (90/80 vs 91/85).

### 2603.05621 v2 — RACAS
- **OPERATION**: each step, a text-only LLM controller writes a visual query, per-camera VLM monitors answer it in text, the controller picks one discrete action, and a curator LLM rewrites a bounded four-part memory (environment, robot state, history, task).
- **INFO ACCESS**: GPT-4.1 or -mini, all frozen; the controller never sees pixels; embodiment knowledge sits only in 3 prompt files; no depth.
- **CLUSTER**: fits K109 good (query-conditioned image→text), with a K301-style bounded memory.
- **WORKS**: Table II, steps to goal: Dingo sim 16.40±0.96 vs random 25.00; limb 9.56±1.50 vs 22.07±0.98 (p<0.01, Holm-corrected); real Dingo 25.80±4.94 (min 7); ROV tank 14.00±1.75; pool 19.20±6.51.
- **FAILS**: localization/approach tasks only; reports steps, not success rate; 5–30 runs; the only baseline is random actions; no ablation of the monitors, the query or the curator (the curator is checked only on Blackjack, appendix); model size changes across platforms (§IV-D); missing depth hurts (§VII).
- **COUNTER**: none.

### 2603.07892 v4 — RoboRouter
- **OPERATION**: embed the task (instruction + image + metadata), retrieve and rerank similar past executions, and let an LLM router pick one pool policy; a VLM evaluator summarizes each run's video and metrics back into the DB and router context.
- **INFO ACCESS**: GPT-4o and the policies (ACT, DP, DP3, RDT, π0, CaP) are frozen; onboarding runs each policy on representative tasks.
- **CLUSTER**: (g) experience-based policy routing.
- **WORKS**: Table 1 (RoboTwin 2.0, 20 tasks): 79.85% vs best single DP3 76.45%. Table 2 (real): 47% vs π0 34%. Table 4: routing accuracy 96.32 / 98.63%. Table 5: without the evaluator, 69.80% / 37%.
- **FAILS**: only +3.4 pts in sim; below the best single policy on several tasks (Put Object Cabinet 69 vs 71, Click Alarmclock 76 vs 77, Open Laptop 86 vs 87); real Adjust Bottle 7/20 vs ACT 8/20; DB built on the evaluated task configurations (inferred); no variance.
- **COUNTER**: every other ablation moves results ≤1.75 pts (Table 5). Without the evaluator (69.80) the router is below DP3 alone.

### 2603.08814 v2 — Scale-Plan
- **OPERATION**: build an action graph from the PDDL domain (effects→preconditions edges); the LLM proposes goal actions, backward DFS collects prerequisites and objects, and an LLM pipeline decomposes, allocates and merges over that filtered set; no problem file, no solver.
- **INFO ACCESS**: GPT-5.2 frozen; handwritten PDDL domain; open loop.
- **CLUSTER**: (a) variant: the symbolic domain prunes the LLM's context rather than the solver gating the plan; also touches (c) allocation.
- **WORKS**: Table II (MAT2-THOR): overall TCR 78% vs LaMMA-P (LLM-corrected) 53%, LLM+P 39%; complex 59 vs 24. Table III: no filtering 66%, LLM shallow filter 67%.
- **FAILS**: 49 tasks on their own cleaned benchmark, single run; planning takes 62.27 s vs 12.83 s (Table IV); no replanning; failures are missing open/release preconditions (§IV-D).
- **COUNTER**: filtering gives no TCR gain on vague tasks (71 vs 71 for No-EF, Table III), and GCR/ER barely move. Almost all of the gain is on complex tasks (59 vs 41–44).

### 2603.11558 v3 — RoboClaw
- **OPERATION**: a VLM agent calls MCP tools (start/switch policy, env summary, call human); for collection it alternates each forward π0.5 skill with a learned reset policy (entangled pair) and keeps the trajectories; at deployment it monitors, retries, switches or escalates.
- **INFO ACCESS**: the VLM is frozen (backbone not named); the π0.5 skills are LoRA-finetuned on the rollouts; success judgement comes from images.
- **CLUSTER**: (d) middleware/MCP orchestration. Close to K107, but the skills are trained, not frozen. EAP self-reset collection is a singleton candidate.
- **WORKS**: Table 3, forward success over 5 iterations: Body Lotion 21→43/50, Lipstick 2→23/50. Table 2: reset policies 36–43/50. Fig 4a/b: manual collection needs 2.16× the human time and 8.04× the interventions. Abstract: +25% long-horizon success, −53.7% human time.
- **FAILS**: each iteration adds 50 samples with no equal-data manual control, so the gain may be data volume (inferred); long-horizon results only in Fig 4(c), and Baseline 2 is a product of subtask rates; one platform; VLM success judge unvalidated.
- **COUNTER**: none.

### 2603.14523 v1 — VLA-Thinker
- **OPERATION**: SFT OpenVLA-OFT on Qwen3-VL-synthesized CoT with ZOOM-IN crop calls, then GRPO on success + format reward; the policy may request a crop before acting.
- **INFO ACCESS**: the 7B student is trained; Qwen3-VL-30B-A3B is used only offline as the CoT teacher; single view, no wrist camera; no proprioception on LIBERO.
- **CLUSTER**: new (k) "train the policy to call a perception tool (crop/zoom) inside its reasoning". The SFT-then-RL half resembles K708, weak.
- **WORKS**: Table 2 (LIBERO): 97.5 vs OFT 91.0; Long 96.9 vs 86.5. Table 3 (RoboTwin): short 62.3 vs 21.3, medium 70.7 vs 47.1, long 64.6 vs 46.5. Table 4: SFT-only 95.0.
- **FAILS**: no ablation separates the zoom tool from text-only CoT or from the extra training; the OFT baseline is a reduced-input variant below its published wrist-camera result (inferred); sim only.
- **COUNTER**: GRPO-only 88.2 is below the 91.0 backbone (Table 4). RL starts at about 0.82 success (Fig 3a), so the zero-reward rationale of K708 is never tested. Place A2B Left gains only +1.6.

### 2603.18210 v1 — GoalVLM
- **OPERATION**: harness builds a depth BEV map and ≤4 frontiers; SpaceOM ranks them via a prompt chain, blended 0.65/0.35 with a UCB value map; SAM3 masks back-projected as goal; FMM drives; 2 agents share maps and split frontiers.
- **INFO ACCESS**: all components frozen; the VLM sees RGB + the frontier list, never numeric map receipts.
- **CLUSTER**: (h): the map stays in the harness and the VLM gives advice by ranking.
- **WORKS**: Table I (GOAT-Bench val_unseen): SR 0.558, SPL 0.183 vs Modular GOAT 0.294 / 0.175.
- **FAILS**: ablations use 50 val_seen episodes, not val_unseen; a multi-agent subtask succeeds if either agent reaches the goal (min distance, §IV-A4), so the comparison with single-agent baselines is not like-for-like; single-agent SR is given as 38.6 (Table II) and 32.0 (§IV-F); SPL 0.183 vs AstraNav 0.569
- **COUNTER**: removing the VLM costs only 0.562→0.540 (Table II). Most of the gain comes from the second agent.

### 2603.18520 v1 — RAPID (EV battery disassembly)
- **OPERATION**: wrap the needed ROS2 service as an explicit SmolAgents tool, versus letting the LLM discover it through an MCP server that exposes 39 generic services plus the target one.
- **INFO ACCESS**: GPT-4o-mini (API) and Qwen3.5 4B/9B (Jetson), all frozen; both conditions share the inventory-JSON tools; the disassembly plan is assumed complete.
- **CLUSTER**: (d) middleware. It is direct contrast evidence for K104/K108: a narrow explicit tool beats open discovery.
- **WORKS**: §IV-D, move 0.2 m: Tool 60/60 correct; MCP failures 1 (GPT-4o-mini), 6 (4B), 0 (9B) out of 20 each. "Remove remaining parts": MCP fails 13/30 (43.3%), 11 of them false successes, vs Tool 0/30. Cost $0.21 vs $0.07. Platform: taught poses 97.06%, one-shot vision 57.35%, servoing 82.84% (Table IV).
- **FAILS**: 2 prompts, 5 parts, n = 10–20 per cell; the MCP arm confounds discovery with 39 distractor services (inferred); no vision-in-the-loop agent.
- **COUNTER**: Qwen3.5 9B went 20/20 under MCP on the simple move.

### 2603.22435 v2 — CaP-X
- **OPERATION**: run a 12-model × 8-tier grid (7 tasks × 100 trials) varying primitive abstraction, single vs multi-turn stdout/stderr, and raw RGB vs a VDM text differencer.
- **INFO ACCESS**: frozen models; S1 uses ground-truth state; human reference by 7 authors.
- **CLUSTER**: fits K801 good (grid over frozen models × harness tiers); its M3 is already a K109 source.
- **WORKS**: §3.3: human reference 88.5% single-turn; success rises monotonically with abstraction (Fig 3); M1 helps every model (Fig 5). Other numbers appear only in figures.
- **FAILS**: the local full text lacks §§4–6, so the CaP-Agent0/CaP-RL claims are unverifiable here; humans debugged iteratively while models were scored zero-shot Pass@1; 7 core tasks.
- **COUNTER**: raw RGB each turn (M2) is worse than text-only M1 (§3.3 Takeaway 3), against giving the coder images.
