# K109 — Insert a separate VLM that turns images into text for the planner
_parent: **Design the Frozen Model's Observation and Action Interface** ([`observe_act_interface`](../main/observe_act_interface.md)) · status: candidate_pattern · source card: `K109-vlm-image-to-text-observation.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
convert camera images into text (scene description, before/after differences, completion judgement) with a separate frozen VLM and feed that to the planner

- Information access: Frozen VLM converter and frozen planner; 2603.22435#s1: the coding agent sees no raw pixels, only the VLM's text plus stdout/stderr; no ground-truth state; 2606.10267#s2: the best variant grounds descriptions with privileged simulator contact information, unavailable on the real robot (bounding boxes used there).
- Contrasts: Information contrast: privileged contact grounding (2606.10267#s2) vs non-privileged differencing (2603.22435#s1).
- Transfer: If the student must reproduce this channel, it inherits a second frontier call; otherwise this is privileged at train time.
- Status: candidate_pattern (2 full-text paper(s))

## When it works
- The strongest available VLM is used as the differencer (2603.22435#s1)
- Tabletop scenes with a Gemini 2.5 Flash planner and fixed horizon (2606.10267#s2)

## When it fails
- No VLM backbone ablation, so the gain is not separated from the converter's own capability; wall time roughly doubles; insertion/pouring remain brittle (2603.22435#s1)
- Best variant relies on privileged contact info (2606.10267#s2)

## Counterexamples
- none found in the readings
