# K503 — Use a frontier LLM with privileged simulator state to iterate a program teacher until it succeeds
_parent: **Generate Supervision with a Privileged Teacher the Student Cannot See** ([`privileged_teacher_supervision`](../main/privileged_teacher_supervision.md)) · status: candidate_pattern · source card: `K503-llm-iterated-privileged-program-teacher.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
have a frontier LLM or coding agent with full simulator state write or revise a solver program from failure logs until it succeeds, and keep its successes as demonstrations for a vision-only student

- Information access: Teacher privileged: object/goal poses, metric depth, segmentation, scene source (2609.27308#s1); ground-truth poses plus failure log, images and success/failure libraries for the LLM tuner (2609.21650#s1); Student (VLA) never sees privileged state and never pilots the harness; teacher runs offline (minutes to hours per episode).
- Contrasts: Contrasts with K501 (teacher acts through the student's own interface).
- Transfer: Raises teacher success through privilege; the student-observability gap is then left to SFT and RL (K708).
- Status: candidate_pattern (2 full-text paper(s))

## When it works
- Full simulator-state access and a long wall-clock budget (2609.27308#s1)
- Single-primitive tasks with a success checker for filtering (2609.21650#s1)

## When it fails
- Hardest tasks unsolved; poor visual grounding, over-commitment to a failing decomposition, scorer hacking (43% Sol, 39% Terra) (2609.27308#s1)
- Multi-step tasks unsupported; top-down grasp fits boxes; privileged inputs replaced by learned perception untested (2609.21650#s1)
