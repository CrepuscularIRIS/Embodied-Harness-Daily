# K107 — Wrap a frozen VLA as a planner-controlled primitive and inspect before committing
_parent: **Let a Frontier Planner Compose Code, Learned Tools and Frozen VLAs** ([`planner_composes_code_and_policies`](../main/planner_composes_code_and_policies.md)) · status: candidate_pattern · source card: `K107-frozen-vla-steered-by-planner.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
wrap a frozen VLA as a primitive the planner stages, bounds, inspects and retries, or whose inputs/outputs it edits before approving

- Information access: VLA frozen, never fine-tuned; planner frozen frontier model; 2607.08448#s1: planner sees depth/world maps and (per its REPL file table) the benchmark success signal; it stages the robot into a VLA-compatible pre-contact state and runs vla_act with a stop predicate; 2609.33378#s1: agent does not see simulator state or the success signal; it can edit the VLA instruction, bias visual-token attention, or override motion, and inspect candidates without advancing the environment.
- Contrasts: Information contrast: 2607.08448#s1 planner can read the success signal, 2609.33378#s1 cannot. Contrasts with K106 (tool trained for the call).
- Transfer: Needs a frozen low-level policy competent in the target domain.
- Status: candidate_pattern (2 full-text paper(s))

## When it works
- The VLA is already competent on in-distribution local contact; metric depth for staging; multi-turn budget (2607.08448#s1)
- The VLA is language-conditioned and exposes attention internals; candidates can be requested without stepping (2609.33378#s1)

## When it fails
- Planner backbone swings results with the harness fixed; Composite-Unseen stays at 13.8-15%; no ablation of analytic primitives vs vla_act; open loop between planner and VLA (2607.08448#s1)
- Tool access without guidance gives 0% on the real robot; instruction/attention edits unreliable on task-specific fine-tuned pi0.5 (2609.33378#s1)

## Counterexamples
- none found in the readings
