# K704 — RL a small coder/planner model directly inside an embodied code harness on sparse success
_parent: **Make Sparse-Success Embodied RL Learnable** ([`teacher_seeded_sparse_rl`](../main/teacher_seeded_sparse_rl.md)) · status: candidate_pattern · source card: `K704-teacher-free-rl-in-embodied-code-harness.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
train a small model with GRPO/PPO on verifiable simulator success inside the code-as-action harness, without teacher trajectories

- Information access: Same harness train/deploy, binary success, frozen VLAs and SAM 3 (2610.01939#s3); Oracle-state rubric reward with VLM captions as text observation (2609.27308#s4); Privileged state APIs during training, real perception at deployment through the same primitives (2603.22435#s4).
- Contrasts: Information contrast across members: what is privileged during training (nothing / reward / perception API).
- Transfer: Needs nonzero base success; with sparse success, groups may be all-zero.
- Status: candidate_pattern (3 full-text paper(s))

## When it works
- Simulators, frozen components as side services, one 8-GPU node (2610.01939#s3)
- Synthetic environments with verifiable oracle rewards (2609.27308#s4)
- Privileged perception during training to avoid noisy rewards (2603.22435#s4)

## When it fails
- Far below GPT-6 Astra; more give-ups; no claim of manipulation skill; single run (2610.01939#s3)
- No held-out evaluation (2609.27308#s4)
- Three simple tasks, per-task training; S2 rewards noisy enough for credit-assignment ambiguity (2603.22435#s4)

- none found in the readings
