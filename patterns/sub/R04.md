# R04 — Expose the robot software stack to the model as protocol-level tools (ROS connectors, MCP servers, policy start/switch calls)
_parent: **Design the Frozen Model's Observation and Action Interface** ([`observe_act_interface`](../main/observe_act_interface.md)) · status: candidate_pattern · source: board-induced 2026-10-21 (wave-1 weak fits)_

## Operation
wrap the robot stack — ROS 2 topics, services and actions, navigation and motion planners, perception, VLA backends and trained skill policies — as tools behind a generic agent protocol (langchain-style connectors, MCP servers generated from ROS message schemas, MCP calls that start, switch, monitor or reset policies), with typed and validated arguments, and let a frozen LLM/VLM agent discover and call them, either through a narrow explicit tool set or through open service discovery

- Information access: Frozen tool-calling LLMs/VLMs in all members; tools carry ROS 2 navigation, MoveIt, open-set detection and depth distance queries (2505.07532#board); tool schemas are generated from ROS messages and VLA backends are swapped behind a fixed I/O contract (2512.10394#board); the agent starts, switches and monitors LoRA-tuned VLA skills and a learned reset policy and judges success from images (2603.11558#board); an explicit tool and an MCP server exposing 39 generic services plus the target one are compared on the same action (2603.18520#board).
- Contrasts: Contrasts with K108 (optional tools beside primitives, studied as a model-side choice; here the object is how the stack is exposed) and K107 (a frozen VLA staged and inspected by a planner; here policies are tools behind a protocol, without staging or inspection).
- Transfer: Robot middleware practice (ROS) met with LLM tool protocols (MCP); transfers wherever the stack is already service-based, but tool-set size and naming become part of the interface the model must ground.
- Status: candidate_pattern (4 member papers, all with full text)

## When it works
- A narrow explicit tool is compared with open discovery on the same action: explicit tools complete 60/60 simple moves and 30/30 multi-part removals, while MCP discovery fails 13/30 removals (43.3%), 11 of them false successes, at $0.21 vs $0.07 per 10 trials (2603.18520#board)
- The protocol layer is checked not to cost task performance: a VLA run inside the middleware keeps LIBERO success (Spatial 99.2 vs 98.6, Object 98.4 vs 97.6 at 1.17x speed with moderate pruning) (2512.10394#board)
- Policy calls include reset and recovery: forward skills improve over 5 collect-and-retrain iterations (21 -> 43/50 and 2 -> 23/50) with learned reset policies at 36-43/50, and manual collection needs 8.04x more human interventions (2603.11558#board)
- Embodiment documents are retrievable by the agent, and HRI and mission control are split into separate agents, tested on a wheeled robot with a digital twin, a simulated arm and a simulated tractor (2505.07532#board)

## When it fails
- Agent-level task success is not measured: the middleware is validated by a VLA benchmark and qualitative cases, and the real robot study "emphasizes feasibility and runtime semantics rather than large-scale statistical performance"; the framework paper reports only qualitative outcomes (2512.10394#board, 2505.07532#board)
- State shared between LLM agents drifts: two LLM agents occasionally disagree about the embodiment, and making LLM agents responsible for mission-state synchronisation causes inconsistencies (2505.07532#board)
- Open discovery produces false completions: under service discovery the agent marks the task done without the needed calls, sometimes without executing anything (2603.18520#board)
- Retraining gains are not separated from data volume: each iteration adds 50 samples with no equal-data manual control, long-horizon results are figure-only, and the VLM success judge is not validated (2603.11558#board)

## Counterexamples
- Discovery is not always worse: one locally deployed 9B model went 20/20 under MCP on the simple move, matching explicit tools (2603.18520#board)
- Aggressive pruning behind the same contract does cost success (Object -7.8, Long -6.6 at the highest preset), so the swap layer is not free (2512.10394#board)
