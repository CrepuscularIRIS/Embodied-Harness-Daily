# K504 — Branch successful teacher runs from saved simulator checkpoints to add recovery and diversity, keeping only verified branches
_parent: **Distil Success-Filtered Teacher Harness Trajectories into a Compact Student** ([`offline_harness_distillation`](../main/offline_harness_distillation.md)) · status: candidate_pattern · source card: `K504-checkpoint-branch-diversification.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
save simulator checkpoints along a successful teacher run, branch from them with injected failures or varied scene/strategy/phase/noise, and keep only branches that pass verification

- Information access: Teacher acts only through the shared harness (student-observable); pipeline has checkpoints, success predicates, perturbation library and human review (2606.18363#s2); Teacher edits scene/grader/solution code with full simulator access; branches replay-checked in 512-env batches; student sees only RGB + proprioception (2609.27308#s3).
- Contrasts: Information contrast: student-observable teacher (2606.18363#s2) vs privileged code teacher (2609.27308#s3).
- Transfer: A cheap substitute for on-policy correction when teacher queries at student states are costly; it still covers only teacher-chosen states.
- Status: candidate_pattern (2 full-text paper(s))

## When it works
- Resettable simulator with state checkpoints (2606.18363#s2, 2609.27308#s3)
- Teacher success high (~90%) so filtering keeps most data (2606.18363#s2)
- A verified solution passing single- and batched-env checks (2609.27308#s3)

## When it fails
- Recovery supervision comes from teacher-visited perturbed states, not student-induced states (2606.18363#s2)
- Only six tasks reach VLA training; pipeline never run end to end; real full-task success 20%; no on-policy correction (2609.27308#s3)

## Counterexamples
- Some seen tasks drop with perturbation data (push basket 86.7 -> 66.7, shell game 70.0 -> 63.3) (2606.18363#s2)
