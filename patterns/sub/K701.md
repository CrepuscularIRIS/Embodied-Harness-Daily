# K701 — Train the policy through an unmodified harness by capturing its model calls at an API proxy
_parent: **Train the Policy Through, or Aligned with, the Deployment Harness** ([`harness_native_rl`](../main/harness_native_rl.md)) · status: candidate_pattern · source card: `K701-api-boundary-proxy-rl.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
redirect the harness's model endpoint to a recording proxy that captures exact contexts, tokens and logprobs, attach outcome reward, and train the open-weight policy for deployment in the same harness

- Information access: Trainer sees only the API boundary, not harness internals; policy white-box; Reward from a post-run evaluator; robot version: VLA, perception and motion frozen, only the planner trained, SFT init from teacher trajectories (2610.28589#s2).
- Contrasts: Contrasts with K704 (no teacher SFT init) and K706 (aligning a separate training scaffold to deployment).
- Transfer: Simulator rollouts cost far more than SWE sandboxes; RL inherits the SFT teacher's coverage gaps.
- Status: candidate_pattern (3 full-text paper(s))

## When it works
- Verifiable outcome reward and a configurable model endpoint (2605.24220#s1, 2608.17393#s1)
- Harness unchanged between training and deployment; SFT initialization (2610.28589#s2)

## When it fails
- Small gain when the base is already harness-aligned (+0.6); SWE only (2605.24220#s1)
- Compacted or rewritten histories are dropped; each harness trained separately (2608.17393#s1)
- Cross-harness transfer not reported; single run (2608.17393#s3)
- RL adds 5.9 pp over SFT; Goal/Spatial stay low where the teacher rarely succeeds; 2,304 episodes up to 7,200 s each (2610.28589#s2)

## Counterexamples
- none found in the readings
