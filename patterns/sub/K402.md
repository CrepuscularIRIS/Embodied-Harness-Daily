# K402 — Teacher revises a text playbook from comparing its own and a light agent's runs; accept when the light agent matches the teacher
_parent: **Revise the Harness Itself from Execution Traces** ([`harness_self_optimization`](../main/harness_self_optimization.md)) · status: case · source card: `K402-teacher-refined-playbook-for-weaker-agent.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
initialize a playbook from teacher rollouts, have the teacher compare teacher vs light-recipient executions and propose revisions, and accept the first revision whose recipient success reaches the teacher's

- Information access: All models frozen; no logits or gradients; knowledge moves teacher -> lighter agent through harness memory, not weights; Teacher sees the recipient's observations, interventions and outcomes on the same dev cases; success signal used only for dev acceptance; Recipient keeps the same harness and the frozen playbook at evaluation.
- Contrasts: Recipient-induced experience makes this the harness-memory analogue of on-policy correction (F6).
- Transfer: A non-parametric alternative to distillation when the student is a weaker frozen model in the same harness.
- Status: case (1 full-text paper(s))

## When it works
- Playbook length and dev-rollout limits held equal; evaluation on held-out initial configurations with a frozen playbook (2609.33378#s2)

## When it fails
- Acceptance rule does not guarantee termination; initial unrefined playbook hurts the recipient; real-robot playbook had to be adapted by the teacher; small eval sets (2609.33378#s2)

## Counterexamples
- Self-refinement by the light agent fails (22.9%) (2609.33378#s2)
