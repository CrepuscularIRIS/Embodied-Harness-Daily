# K301 — Rebuild each call's context from a bounded within-episode selection with retrieval for the rest
_parent: **Build Context, Notes and Skills with the Weights Frozen** ([`harness_memory_skill_reuse`](../main/harness_memory_skill_reuse.md)) · status: candidate_pattern · source card: `K301-bounded-within-episode-context.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
rebuild each model call from a short window of recent records/images plus a compact map or graph, and give access to older history only by retrieval

- Information access: Frozen model; within-episode only; Model-pulled recall: recall(node, view) over cached views with a SLAM BEV map (2606.10577#s3); search_history/read_history tools with K images, N text exchanges auto-included (2609.29389#s3); Harness-ranked retrieval: event memory plus spatiotemporal graph ranked by relevance, recency, salience and failure penalty (2609.15195#s2).
- Contrasts: Sub-conditions differ in who selects context: the model (recall tools) vs the harness (ranked retrieval).
- Transfer: Context length is a student constraint; a bounded window is what a small student can afford, but none of the members trains a student on it.
- Status: candidate_pattern (3 full-text paper(s))

## When it works
- SLAM localization available for the map (2606.10577#s3)
- Model and episodes fixed across variants (2609.15195#s2)

## When it fails
- A task-progress record can propagate a wrong judgement (authors' interpretation, untested) (2606.10577#s3)
- Only the automatic context window is ablated, on 18 cases single-run (2609.29389#s3)
- Cumulative single-run ablation; graph adds only +1 SR on ObjectNav (2609.15195#s2)
