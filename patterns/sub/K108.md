# K108 — Offer extra tools as optional calls beside primitive actions and let the model choose
_parent: **Design the Frozen Model's Observation and Action Interface** ([`observe_act_interface`](../main/observe_act_interface.md)) · status: candidate_pattern · source card: `K108-optional-tools-alongside-primitives.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
add perception/navigation or MCP tools as optional calls next to the primitive interface rather than replacing it, and let the model decide when to call them

- Information access: Frozen models in both; 2607.26148#s2 tools use panoramic views, a published waypoint predictor and ORB-SLAM3, no ground-truth poses; 2608.03327#s1 tools retrieved by BM25 per active app; Same harness, toggled tools; no student training in these signatures.
- Contrasts: Contrasts with K102 (tools as the only perception path).
- Transfer: Predicts that a tool helpful to a weak student may be neutral for the frontier teacher, so teacher-measured tool value may not transfer to the student.
- Status: candidate_pattern (2 full-text paper(s))

## When it works
- R2R-CE with Opus-5.5 over three runs (2607.26148#s2)
- Harness parse/coordinate/feedback correctness verified before comparison (2608.03327#s1)

## When it fails
- The same tool can help weak and not strong models: tool effects interact with the backbone; several settings single runs (2607.26148#s2)
- Two checkpoints differ in more than reasoning; association not mechanism; one backbone family (2608.03327#s1)

## Counterexamples
- none found in the readings
