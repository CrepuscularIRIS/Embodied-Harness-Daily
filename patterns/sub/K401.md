# K401 — With the model frozen, let an optimizer agent revise the harness from raw traces and keep improvements
_parent: **Revise the Harness Itself from Execution Traces** ([`harness_self_optimization`](../main/harness_self_optimization.md)) · status: candidate_pattern · source card: `K401-trace-driven-harness-revision.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
let a coding-agent optimizer read prior harness code and raw execution traces, propose harness edits, evaluate them on a search set, and keep improvements

- Information access: Agent model frozen; only harness code/prompts/notes change; Proposer sees all candidates' code, scores and raw traces, never test results (2603.28052#s1); Optimizer barred from hidden simulator state, rewards and held-out data; sparse environment feedback (2610.08432#s1); Improver aggregates 16 workers' traces and ground-truth simulator feedback in navigation campaigns; no acceptance gate (2609.39207#s3).
- Contrasts: Contrasts with K403 (same revision step, but interleaved with weight training) and K402 (revision accepted on a weaker recipient's success).
- Transfer: Each candidate costs a batch of simulator episodes; with low teacher success the search signal is coarse.
- Status: candidate_pattern (3 full-text paper(s))

## When it works
- A strong coding-agent proposer and cheap enough evaluation for tens of candidates; search set separate from test (2603.28052#s1)
- Raw execution traces rather than scores or summaries given to the optimizer (2603.28052#s2)
- Enough search episodes per iteration; external vision tools to orchestrate (2610.08432#s1)
- Subtasks share environment and action space when a single harness is shared; gain/loss traces inspected to gate the revision (2610.08432#s2)

## When it fails
- Only one proposer studied; TerminalBench-2 search equals test; component contributions not ablated (2603.28052#s1)
- Trace-vs-score ablation only on text classification (2603.28052#s2)
- Best search-set harness not always best held-out; held-out can plateau or decline (2610.08432#s1)
- In manipulation the shared harness stays below separately optimized ones (2610.08432#s2)
- Navigation gains measured on the same recurring tasks with ground-truth feedback; EQA non-monotonic across passes (2609.39207#s3)

## Counterexamples
- Emerging overfitting of the harness to the search split (2610.08432#s1)
