# K102 — Keep dense geometry inside harness tools and return numeric receipts to the model on request
_parent: **Design the Frozen Model's Observation and Action Interface** ([`observe_act_interface`](../main/observe_act_interface.md)) · status: candidate_pattern · source card: `K102-perception-as-tools-receipts.md` (frozen domain `embodied-agent-harness/v1`)_

## Operation
hold depth, point clouds, calibration and maps inside tools and let the model query pixels, regions or map entries, receiving compact numeric receipts before it commits motion

- Information access: Frozen VLM/coding agent; perception models (SAM 3, TAPNext++, GraspGen, OWLv2/Boxer) frozen as tools; Model never receives dense depth arrays or point clouds; it receives depth statistics, measured 3D points, plane fits, region-TCP displacements, or object-level map boxes; No ground-truth object poses; map built from observations and cleared at reset (2610.12549#s3).
- Contrasts: Contrasts with K101 (no depth at all) and K103 (depth used inside the executor of a proposed target rather than returned as a receipt).
- Transfer: Depends on calibrated metric depth; with uncalibrated or scene-dependent depth scaling the receipts would need per-scene calibration or a relative-depth form, which no member tests.
- Status: candidate_pattern (3 full-text paper(s))

## When it works
- Depth is calibrated and metric, consistent with camera calibration (2606.10577#s2, 2609.29389#s1)
- Reasoning tools do not advance the simulator, while action tools report achieved motion and residual error (2609.29389#s1)
- Map entries are treated as cues and verified by close-range perception; task areas spatially separated (2610.12549#s3)

## When it fails
- Behaviour with non-metric or scene-dependent depth scaling is untested (2606.10577#s2)
- Paired comparison changes perception, memory, motion and completion feedback together (18 trials); benchmark conditions overlap with harness development (2609.29389#s1)
- Articulated/multi-stage contact lower (63.3%), two-arm handover 5% (2609.29389#s1)
- Map missed a fallen object's new location; stale labels confused assessment; map ablation removes it from execution and diagnosis together (2610.12549#s3)

- none found in the readings
