# Design the Frozen Model's Observation and Action Interface
_id: `observe_act_interface` · sub-patterns: K101, K102, K103, K104, K108, K109, K110 · 6 candidate_pattern · 1 case · domain: `embodied-agent-harness/v1` · outcome labels: none in this build_

**Definition.** Treat the schema between a frozen frontier model and the environment as the design object: a non-advancing observe tool plus bounded primitive steps with recovery and stopping left to the model (K101), dense geometry kept inside tools and returned as numeric receipts on request (K102), a model-proposed visual target that the harness back-projects, checks for feasibility and executes or sends back (K103), a fixed semantic action vocabulary mapped to a deterministic or frozen executor (K104), extra tools offered as optional calls beside primitives (K108), and a separate VLM that turns images into text for the planner (K109). As a cross-domain case it holds compact LM-oriented commands that replace a raw shell (K110).

**Operational signature.** frozen frontier model → observe (RGB on request, numeric receipts, VLM text) without advancing the simulator → emit a primitive batch, semantic unit, pixel/pose target or optional tool call → harness grounds it (depth back-projection, IK/planner, interpreter, point-goal executor) → returns achieved motion, residuals or feasibility feedback → model continues, recovers or stops

**When to apply.** When a strong frontier model is the policy (usually the teacher) and the bottleneck is how it reads observations and emits actions rather than physical contact; the simulator can answer observation and reasoning calls without advancing time; and depth and calibration are available to the tools.

## Success conditions
_Derived from the member cards' When-it-works lines and the readings' reported effects; each is phrased as a property checkable in a paper's text._
- **Interface elements swapped with the backbone fixed.** One interface element is changed while the model stays fixed: replacing the target-plus-planner action tool with a waypoint predictor lowers R2R-CE SR/SPL 76/66.50 -> 66/57.73, and removing the depth tool gives SR 60 vs 76 (depth-image input instead: 69) (2606.10577#s1, 2606.10577#s2); compact LM-oriented commands beat shell-only interaction 18.0% vs 11.0% on SWE-bench Lite with one model (2405.15793#s1).
- **Observation calls do not advance the world; actions report achieved motion.** Observe and reasoning tools leave the simulator where it is, action tools return achieved motion and residual error, and turn and wall-clock caps are stated; a minimal observe/step interface reaches R2R-CE-100 SR 75.7 +/- 1.5 (medium) and 81.3 +/- 2.5 (ultra effort) over 3 runs each (2607.26148#s1, 2609.29861#s1, 2609.29389#s1).
- **Geometry stays inside tools on calibrated metric depth.** Depth, point clouds, calibration and maps are held by tools; the model gets receipts (depth statistics, measured points, plane fits, map boxes) or picks a target the tool back-projects; the depth is calibrated and metric. A perception-augmented interface lifts a paired 18-trial comparison 61.1% -> 88.9%, and map entries are verified by close-range perception (2606.10577#s2, 2609.29389#s1, 2610.12549#s3, 2609.29964#s1).
- **Semantic vocabulary follows embodiment conventions over a reliable executor.** Model output is restricted to semantic units or entity calls that an interpreter or frozen point-goal navigator executes; units follow motion conventions (arbitrary symbols succeed 1/20), and a scene-graph entity interface reaches 39.7% SR / 19.7% SPL on 3000 HM3D-OVON val_unseen episodes (2609.10522#s1, 2606.27871#s1).
- **Extra tools are optional and checked per backbone.** Tools are added beside primitives rather than replacing them, harness parse/coordinate/feedback correctness is verified before comparison, and effects are reported per model: optional hybrid tools raise the strongest model 82.3 -> 85.7 SR at 0.59x calls, while imposed waypoints lift weak models (5 -> 43 SR) and move strong ones by <=2 points (2607.26148#s2, 2608.03327#s1).
- **Image-to-text conversion compared with raw images.** A separate VLM's text (visual differencing or grounded descriptions) is compared against raw RGB in the same loop: text differencing beats raw image interleaving, which degrades relative to text-only feedback; bounding-box and contact-grounded descriptions reach 47.90% / 52.36% vs 38.84% image-only long-horizon success (2603.22435#s1, 2606.10267#s2).

## Failure modes
_Derived from the member cards' When-it-fails lines; each names a design or evidence property whose presence signals the failure._
- **Wrong stop and wrong target dominate what is left.** Residual failures are wrong target/route and wrong stop (15/44 each in one 126-failure audit), runs that enter the goal radius but stop elsewhere, and 8/100 tasks failing in all six runs (2607.26148#s1, 2609.29861#s1).
- **Requested rather than realized motion.** Step returns report requested motion: forward batches stall with pixel-identical views and inconsistent recovery, and on a physical quadruped the agent under-rotates without realized-motion feedback and lacks body awareness (2609.29861#s1, 2607.26148#s1).
- **Depth assumption untested.** Tools assume calibrated metric depth and targets are restricted to visible pixels with valid depth; behaviour under non-metric or scene-dependent depth scaling is untested (2606.10577#s2, 2606.10577#s1).
- **Interface bundle compared instead of components.** A paired comparison changes perception, memory, motion and completion feedback together on 18 trials; no harness-component ablation for scene-graph entity calls; contact views, rehearsal and drag correction are not ablated separately (2609.29389#s1, 2606.27871#s1, 2609.29964#s1).
- **Tool value depends on the backbone.** The same tool helps weak and not strong models; injecting MCP tools gives +4.0 pp for a thinking checkpoint and -5.9 pp for an instruct one, and the two checkpoints differ in more than reasoning (2607.26148#s2, 2608.03327#s1).
- **Gain carried by the converter or a privileged channel.** No VLM-backbone ablation separates the converter's own capability, and wall time roughly doubles (cube stack 60.8 s -> 113.6 s); the best description variant relies on simulator-privileged contact information unavailable on the real robot (2603.22435#s1, 2606.10267#s2).
- **Latency and contamination unaccounted.** 3-19 s per call and high inference cost; benchmark contamination of proprietary models cannot be verified; mostly single runs on 100-episode subsets (2607.26148#s1, 2609.29861#s1).

## Reviewer expectations
_From `profile/expectations.json`; ids are stable across the domain._
- **E01 (ablation, common_practice).** Hold the frontier backbone fixed and compare the proposed harness with at least one alternative harness or loop organization on the same episodes. For zero-shot VLN-CE the alternative is a rerun of a published zero-shot harness or workflow (2606.10577#s4, 2609.15195#s4) with the same model; for coding agents, a second deployable harness. — _applies when_ a claim that a harness (rather than the model) raises embodied or agentic success.
- **E02 (ablation, common_practice).** Attribute a gain to a harness component only through one-at-a-time toggles (leave-one-out or single add) with the backbone fixed. A cumulative stack (A, then +B, then +C) or a bundle-level comparison does not separate components or their interactions. — _applies when_ a claim that a specific harness component (depth tool, memory, verifier, skill library, plugin, feedback channel) causes the improvement.
- **E03 (ablation, common_practice).** Report the harness or tool effect under at least two backbones of different strength. Several read papers find that tools and imposed structure help weak models and are neutral or harmful for strong ones. A gain measured on the teacher therefore does not predict the gain for a compact student. — _applies when_ a claim that a harness component or tool helps in general, or that a teacher-measured tool value will carry to a student.
- **E05 (metric, common_practice).** Report cost alongside success: model calls, input and output tokens, wall-clock or per-call latency, and USD per episode or per solved task, including failed trials. Harnesses with similar pass rates can differ about 40x in tokens per solved task. — _applies when_ a claim that a harness, interface or distilled student is better or more practical than an alternative.
- **E06 (dataset, common_practice).** For a VLN-CE harness, report SR, SPL, OSR and NE on R2R-CE val_unseen, either on the shared 100-episode zero-shot subset or the full split. State which one, and do not mix subset results with full-split numbers of trained methods as if they were matched. — _applies when_ an empirical claim about a zero-shot or harness-based VLN-CE / ObjectNav agent.
- **E08 (reproducibility, common_practice).** State contamination and development-overlap caveats. Frontier 'zero-shot' describes how the model was used, not what it was trained on. Disclose whether the evaluation tasks were used during harness development, and whether ablations ran under a privileged action space that is not comparable to the benchmark protocol. — _applies when_ a benchmark claim by a frontier-model harness, or ablations run under non-standard execution.
- **E16 (metric, common_practice).** Break failures down by endpoint as well as SR: never reached vs reached but wrong stop (the OSR-SR gap), false completion declarations, stuck or no-progress runs, and per-task repeat patterns. Stopping is the dominant residual failure in the read navigation papers. — _applies when_ an embodied navigation or manipulation agent's success claim, especially one that adds a stop or completion check.
- **E20 (other, common_practice).** State the depth assumption behind depth-based perception tools (pixel depth queries, back-projection, stop checks): whether depth is metric and calibrated, and whether behaviour under non-metric or scene-dependent depth was tested. — _applies when_ a harness whose tools or gates convert depth readings into distances, targets or stop decisions.
- **E22 (reproducibility, common_practice).** Compare interfaces and harnesses at a matched interaction budget: the same caps on LLM calls, turns, wall-clock time and GPU. Disclose any asymmetry, such as uncapped turns or extra compute for tool runs, because budget endings drive many success differences. — _applies when_ a comparison between harnesses, interfaces or tool bundles with the model fixed.

## Cognitive barriers
- "A stronger model needs less harness." Imposed structure helps weak models and is neutral for strong ones, yet optional tools and depth receipts still raise the strongest backbones (82.3 -> 85.7 SR; SR 60 -> 76 with the depth tool) (2607.26148#s2, 2606.10577#s2).
- "The frontier model can look after itself." With only RGB on request and requested-motion returns, the residual failures are stopping, stuck batches and missing body awareness (2609.29861#s1, 2607.26148#s1).
