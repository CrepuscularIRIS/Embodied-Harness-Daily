# embodied：领域卡匹配索引

从现有卡片直接提取名称和操作签名，剔除录用/论文数量等统计；按需回原卡看适用条件和反例。它是检索入口，不替代完整卡片或原文证据。

| 主卡 ID | 名称 | 操作签名 |
|---|---|---|
| embodied:code_policy_trial_revision | Write the Policy as Code and Rewrite It from Trial Diagnostics | task + primitive API → LLM / coding agent writes controller program → static checks → run trials in simulation → diagnose (symbolic logs, phase outcomes, key frames, VLM critique of images or video) → rewrite program → repeat to success or budget → deploy the program (no model at run time) |
| embodied:external_verification_control | Gate, Monitor and Diagnose Actions Outside the Model | model proposes → external checker (linter, argument/provenance/reachability check, fresh-depth STOP check, obstacle clearance) dispatches or rejects with feedback → executor runs → success detector or progress monitor fires → planner advances or replans → (resettable simulation) diagnose after scoring, or backtrack from checkpoints |
| embodied:harness_effect_evaluation | Separate the Harness Effect from the Model Effect | fix tasks, sandbox, verifier and budgets → cross models x harnesses (or toggle one component, or swap one factor on fixed episodes) → repeat runs → paired task-level statistics (bootstrap CI, permutation, sign tests) → classify failures by endpoint and per-task repeat pattern → re-price from raw usage and reconcile cost |
| embodied:harness_memory_skill_reuse | Build Context, Notes and Skills with the Weights Frozen | run episodes → (within episode) keep recent records + compact map/graph, retrieve older content by model-pulled recall or harness-ranked retrieval → (across episodes) summarize into notes, mine and review skills, or compile replay cards → inject into later contexts or replay with anchors re-localized |
| embodied:harness_native_rl | Train the Policy Through, or Aligned with, the Deployment Harness | point the unmodified harness at a recording proxy → capture contexts, tokens, logprobs → assemble prefix chains, mask harness-inserted tokens → screen tasks to intermediate base success, hide verifier-only state, block egress → outcome reward from a post-run evaluator → group-relative update with rollout-level baselines → deploy in the same harness and context rules |
| embodied:harness_self_optimization | Revise the Harness Itself from Execution Traces | run the harness on a search/dev set → optimizer reads prior harness code and raw traces (and the recipient's runs) → proposes edits → evaluates candidates with the same model or checkpoint → accepts by gate → optionally an RL block on the weights → repeat → report held-out |
| embodied:learner_state_teacher_correction | Correct, Review or Relabel at Learner-Induced States | student rolls out in its harness → locate first error / intercept proposal / gate flags state → teacher (black-box frontier, privileged expert or label generator) repairs, replaces or relabels → admission check (final answer, grounding filter, paired-advantage bound from snapshot restore) → SFT/BC on admitted data, or reset RL to correction-derived states → deploy without teacher |
| embodied:llm_symbolic_solver_planning | Let a Solver Plan from an LLM-Written Formal Model | instruction + scene (text state, or image + geometry text) → frozen LLM/VLM writes the formal model (PDDL / Prolog KB / SMT constraints / scheduling graph / search code) → solver or search plans, validates or prunes → on failure, structured feedback to the LLM → repair (bounded rounds) → compile to behaviour trees, skill calls or robot programs → execute (mostly open loop) |
| embodied:multi_robot_llm_coordination | Allocate and Repair Multi-Robot Plans with LLM Agents | task + robot capabilities + shared state → allocator LLM(s) (central manager / grouped negotiators / per-robot agents) → per-robot subtasks or multi-step action chains → feasibility / conflict check (executor-LLM feedback, rule validator, role selector, event filter) → reallocate or renegotiate affected subtasks → per-robot execution (skills or composed code) |
| embodied:observe_act_interface | Design the Frozen Model's Observation and Action Interface | frozen frontier model → observe (RGB on request, numeric receipts, VLM text) without advancing the simulator → emit a primitive batch, semantic unit, pixel/pose target or optional tool call → harness grounds it (depth back-projection, IK/planner, interpreter, point-goal executor) → returns achieved motion, residuals or feasibility feedback → model continues, recovers or stops |
| embodied:offline_harness_distillation | Distil Success-Filtered Teacher Harness Trajectories into a Compact Student | frontier teacher runs the harness → log per-turn reasoning + tool call → keep successful episodes (plus verified branches from checkpoints with injected failures) → drop or rewrite turns that depend on removed components → SFT a compact VLM (LoRA, vision encoder frozen) → optional GRPO in the same harness → deploy with the full or a reduced harness |
| embodied:on_policy_distillation_objectives | Distil On-Policy with Logit, Privileged-Self, Agreement or Harness-Contrast Signals | student samples at its own states → teacher signal: white-box logits / same weights with privileged context / joint privileged view / privileged-self sampled actions / black-box teacher actions matched by a judge / with-vs-without-harness teacher pair → per-token divergence, agreement reward or preference loss (often with a gate or validity filter) → policy-gradient or preference update → deploy without privilege |
| embodied:planner_composes_code_and_policies | Let a Frontier Planner Compose Code, Learned Tools and Frozen VLAs | frozen planner in a coding runtime → writes code cells or typed calls → primitives / learned tool policy / frozen VLA execute (stop predicate, progress head, candidate inspection without stepping) → only requested observations return → planner branches, retries, stages or replans |
| embodied:privileged_teacher_supervision | Generate Supervision with a Privileged Teacher the Student Cannot See | privileged simulator state (poses, masks, metric depth, paths, bearings) → teacher (LLM-iterated program, rule teacher in the student's vocabulary, frozen differentiable expert) → success-checked demonstrations or state targets → student trained on cameras, proprioception and instruction only |
| embodied:sample_verify_select | Sample Candidate Actions and Let a Verifier Choose | observation + instruction → policy samples N candidates (optionally perturbed around a fitted Gaussian) → verifier scores each (learned reward model / same-model verification prompts / reflector) → execute argmax → (optional) hindsight reflection on the outcome → test-time update of policy and critic |
| embodied:teacher_seeded_sparse_rl | Make Sparse-Success Embodied RL Learnable | (optional) SFT on teacher-derived data until every task has nonzero success → roll out the student in the harness (forked per step, or with rollout-only hints) → binary success, rubric or privileged dense reward → GRPO/PPO/Flow-GRPO → evaluate without hints or privilege |
| embodied:trained_vlm_vla_hierarchy | Train the High-Level VLM That Commands a Low-Level Policy | robot data → segment into skills / motions and label (human annotation, larger-VLM back-generated prompts and interjections, human corrections, LLM-generated plans) → fine-tune the high-level VLM → (low level trained on the same command vocabulary) → at run time high level emits command every step-interval or on utterance / failure → low-level policy executes → (optional) trained correction module rewrites the command |
