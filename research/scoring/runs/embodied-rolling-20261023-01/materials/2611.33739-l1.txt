===ABSTRACT===
Code-as-Policy agents generate, execute, and revise robot programs, but often lack explicit mechanisms to govern what persists across executions: which actions are retained within a trial and which code modifications carry over to subsequent runs. This leaves two critical aspects of agent behavior insufficiently controlled: step-level execution and cross-run adaptation. We present RegHarness, a two-level harness that governs both forms of persistence for the RATs agent team, without relying on a vision-language-action (VLA) policy or demonstrations. Within each trial, run-time governance evaluates each proposed step from a reset scene, replaying the committed steps, while a fixed-rule controller commits the step only when both RATs' verifier and a task-long LLM auditor approve it. Between runs, a coding agent uses logged failures to develop and test revisions to skills, primitives, and rules, which remain disabled by default until explicitly enabled by the authors. Using a single low-cost model across all run-time roles, RegHarness achieves an 87.8% success rate (158/180) on paired LIBERO-PRO trials, compared with 39.4% for RATs, and a 72.0% success rate on MolmoSpaces trials. A $2\times2$ ablation study of RegHarness's two levels shows that its skill refinement alone increases RATs' successful trials from 71 to 135, whereas run-time governance alone achieves 105 and RATs' native stepwise reset-and-replay mode achieves only 46. These findings suggest that, for Code-as-Policy agents operating with low-cost models, task success depends not only on how generated programs are executed, but also on the quality of the reusable skills they invoke and how those skills evolve across runs.

===INTRO===
Consider the task in : pick the black bowl on top of a cabinet and place it on a plate. RATs [ 26 ] , a Code-as-Policy [ 15 ] agent team that we run with a low-cost language model, makes six attempts at this LIBERO-PRO [ 32 ] task, each a program for the whole plan. Its static checker rejects one program before it runs, and none of the five that run lifts the bowl: the first leaves it on the cabinet, the last two knock it onto the table. Over the 180 paired LIBERO-PRO trials, RATs solves 39.4% (71/180) within six attempts but only 13 on the first. In its published loop, RATs judges each step only after the whole program has run; a retry, though prompted to keep what worked, is a complete program run again from the reset scene, so a passed step can change and must pass again. All 692 retries are complete programs, and 86% (493/574) of those that follow a diagnosed failure change code outside the failed step (criteria in the supplementary material). Nor does a clean verdict mean the work is done: in 117 of the 670 failed executions, the verifier flags no failed step. What these agents lack is a rule for what to keep: which executed steps stay committed within a trial, and which code changes carry over to the next run. Testing one step at a time does not supply it by itself: the released RATs code already contains a stepwise mode, off by default and not described in its paper, that resets the scene and replays the passed steps before every try, but it commits a step on the verifier’s pass alone and, once a step’s tries run out, commits the step unverified so that the plan can go on. A reset protects a retried step from what the failed test left behind, but it also erases what that test revealed; a trial therefore needs a memory that outlives the reset, and a commit rule that never keeps an unverified step instead of letting the coder’s next program decide which code survives. Between runs, the code itself must change: even after we add such a commit rule to RATs ( + Harness , Sec. 4.3 ), 75 of the 180 trials still fail, 30 of them at a grasp that never lifts a non-flat object (19) or at a placement off target (11). RegHarness regulates what persists at these two time scales ( Fig. 2 ). Within a trial, it wraps RATs’ planner, coder and verifier and reuses the executor of the stepwise mode, so every step test resets the scene and replays the committed steps (reset-and-replay); one LLM auditor per trial audits plans, code, step tests and finished plans that fail the benchmark’s task check, and a controller of six fixed rules turns its proposal and the remaining budget into commit , retry , replan or abort , never committing a step that the verifier has not passed. Between runs, a coding agent (Claude Opus 5.5 in Claude Code) reads full trial logs and frames and turns each fix to skills, primitives or rules into a default-off switch that must pass tests, and a byte-for-byte equivalence check when off, before the authors can enable it. Reset-and-replay, which needs a scene that software can reset, is confined to simulation. Coding agents and optimizers already revise robot harnesses and skills between runs [ 6 , 18 , 25 , 4 , 29 , 5 ] , most of them behind an automatic acceptance test that our author-gated loop lacks, and the concurrent RegenHarness separates a model’s proposal from a deterministic commit gate on a quadruped [ 23 ] . RegHarness is a new harness framework that improves RATs in two ways, without a VLA policy or demonstrations: within a trial it replaces RATs’ loop with a commit rule over steps tested from a reset scene, and between runs it refines the skill library that RATs shares across tasks. With one low-cost model in every role, RegHarness solves 158 of the 180 LIBERO-PRO trials on initial states 0–2 (87.8%), where RATs solves 71 (39.4%), and 260 of 300 (86.7%) over five initial states; on MolmoSpaces it solves 72.0% (144/200). The 2 \times 2 splits this gain unevenly between RegHarness’s two levels: its refined skills add 64 trials under RATs’ loop and 53 under run-time governance, whereas replacing RATs’ loop with run-time governance adds 34 trials with the released skills and 23 with the refined ones (exact McNemar p=1.2\times 10^{-4} and 2.9\times 10^{-4} ). RATs’ own stepwise mode solves 46, fewer than RATs itself, so the reset alone does not explain the margin of run-time governance. A RegHarness trial costs an estimated CNY 2.16 (about US$0.32 at CNY 6.67 per US$) in model calls, against 1.51 (US$0.23) for RATs ( Sec. 4.5 ). Both levels were debugged on initial state 0 only and tested directly on states 1–4 ( Sec. 4.1 ).
