# Embodied First Exam

## Abstract
Early successes on agentic robotics point to a potential paradigm shift toward using coding agents to control robots. Existing robotics benchmarks are built around visuomotor policy learning, leaving it open whether coding agents can reliably control diverse robots under physical-world constraints. We therefore introduce the Embodied First Exam, a unified, comprehensive, and agent-native evaluation framework where coding agents can choose their own control approach: direct control, code to control, or train a policy to control. We hope it serves as a first exam for coding agents before they enter the physical world, with 1,156 tasks in 35 suites on 47 robots, including 9 new suites that go beyond pick-and-place to spatial puzzles, dexterous manipulation, multi-robot interaction, dynamic whole-body control, and sim-to-sim engineering. Each task can be run in up to three evaluation settings. The Standard Setting mimics the real world: the agent receives only sensor observations and, by default, cannot reset the environment. Its Realtime variant keeps the environment running while the agent reasons. The Privileged Setting gives the agent access to the full simulator state and unlimited resets, allowing it to search for an oracle solution for training purposes. Success rates in this setting serve as an approximate upper bound. On the 456 core tasks, the strongest of eight agents, GPT-6 Astra in Codex, achieves a success rate of 34% in the Standard Setting, leaving much room for improvement. To see where agents fail, we label the stage at which failed attempts go wrong and compare failures across agents, settings, and stage categories.

## 1 Introduction
Robots acquire new skills either by manual programming or by learning from data, as in recent vision-language-action models [ 11 , 69 , 10 , 122 , 110 , 38 ] and world action models [ 182 , 159 , 133 ] . Coding agents powered by large language models suggest a third way. They already complete challenging software engineering tasks in the digital world [ 64 , 102 , 104 , 73 ] . What makes these agents promising for robotic engineering is their capabilities to turn instructions into executable code and revise their plans through automated experimentation [ 84 , 141 , 151 ] . Recent early success in agentic robots suggests such a potential paradigm shift, where agents directly control robots [ 47 , 191 , 199 , 130 ] , write robot programs [ 62 , 32 , 101 , 167 , 145 , 48 ] , or train policies [ 165 , 83 ] . This motivates a systematic assessment of the capability boundary of coding agents: What robotic tasks can general-purpose coding agents solve, under what physical-world constraints, and where do they fail? Existing benchmarks do not yet fully address this question. The capability boundary cannot be established from a focused set of robotics tasks [ 59 , 184 , 87 , 76 , 106 , 16 ] , nor from automated programming tasks without imposing physical-world constraints [ 64 , 102 , 198 , 168 , 14 , 116 ] . This requires defining which robotic capabilities to evaluate, measuring how physical-world constraints affect success, and supporting different models and harnesses through task interfaces. To answer this question, we introduce the Embodied First Exam (EFE) , a unified evaluation framework that connects coding agents to simulated robots ( ), following three principles. First, include diverse tasks that go beyond pick-and-place. Spatial puzzles test reasoning about spatial constraints, while sim-to-sim engineering tests how agents revise controllers from execution feedback under unfamiliar dynamics. Dynamic tasks test responses to a changing world. Multi-robot interaction and whole-body control test coordination. EFE therefore contains 1,156 tasks in 35 suites on 47 robots. It combines 26 suites adapted from existing robotics benchmarks with 9 new suites covering these capabilities and safety. Second, measure how success depends on physical-world constraints. Its tasks should follow the constraints of a real robot as closely as possible. Success with full simulator state and resets does not establish what an agent can achieve through partial observations, with no resets, or while the dynamic world keeps running. We therefore define up to three evaluation settings per task. Standard Setting follows real-robot conditions: the agent observes the environment only through the robot’s sensors and cannot reset it by default. The simulation waits while the agent reasons, and its Realtime variant keeps the environment running while the agent makes decisions. Privileged Setting provides an approximate upper bound and can be used to generate training data, where the agent has access to the full simulator state and unlimited resets, allowing it to search for an oracle solution by trial and error. We call each <task–setting> pair a test . Tests of the same task share the initial scene and success rule, allowing us to compare success as state access, reset limits, and timing change. Third, provide unified infrastructure for different models, harnesses, and control approaches. With a single command, EFE runs different combinations of models and harnesses across diverse robotics tasks. Given a natural-language task instruction, the agent chooses its control approach ( Figure 1 ). In Direct control , it directly outputs actions after receiving observations [ 47 , 191 , 199 ] . In Code to control , it outputs a planner, controller, or other program that generates the robot’s actions [ 84 ] . In Train a policy , it trains a policy in simulation and uses it to control the robot [ 95 , 83 ] . The framework enforces the access permitted by each evaluation setting, and a verifier outside the agent’s control grades every attempt [ 203 , 196 ] . We evaluate eight coding agents on a core set of 456 hard tasks. The strongest agent, GPT-6 Astra [ 115 ] in Codex, solves 77% of the Privileged tests but only 30% of the Standard tests of the same 391 tasks. Apart from the three strongest agents, GPT-6 Astra, Claude Opus 5.5 and Gemini 4 Argon, the best result comes from Kimi 3.1 Pro, which solves 9% of the Standard tests of the same 391 tasks (34 tests, Figure 10 ) and 7% of the Realtime tests ( Figure 7 ). The Realtime Setting is harder still: 63% of its tests remain unsolved by any agent, compared with 50% of the Standard tests of the same 54 tasks. To identify where failures occur within a task, we divide each task into stages. Each stage corresponds to a change in the world required to complete the task. ## 2 The Embodied First Exam: A Unified Evaluation Framework for Coding Agents in Robotics
In this section, we describe how we evaluate coding agents on robotics tasks ( Section 2.1 ), the resource constraints of each task ( Section 2.2 ), and the tasks of the exam ( Section 2.3 ). 2.1 Framework and Evaluation Protocol Existing robotics benchmarks focus on visuomotor policy learning with a relatively fixed input-output interface, whereas we evaluate coding agents that can choose their own control approach. Our design principle is therefore to give the agent broad freedom over how it acts and to constrain only the result: we fix where it starts, what resources it gets, and how success is checked. To achieve this, we package every robotics task in the format of Harbor [ 44 ] , the evaluation framework of Terminal-Bench [ 102 ] , which runs the task in containers, as shown in Figure 2(a) . The agent has its own workspace, where it can install packages, write and run programs, and train models. Each task starts from a fixed initial state; a verifier outside the agent’s container reports whether the agent’s answer meets the task’s success rule. On top of this framework, we define a unified evaluation protocol with up to three settings per task ( Figure 2(b) ). We design Privileged as an approximate upper bound on performance, with full access to the simulator for trial and error, while Standard and Realtime make the evaluation as close to a real robot as possible. The bound holds over a set of tasks, not for every single task, because an agent can solve a task in Standard that it fails in Privileged ( Appendix D ). For a given task, all settings share the same initial scene, success rule, and time limit, so their results are paired. They differ in what the agent observes, whether it can reset, whether the world waits, and where the simulator and the verifier run, never in the control approach the agent may choose. We ablate the first two differences in Section 3.2 . Privileged. In Privileged , the agent runs in the same container as the simulator, so it can read the full simulation state and reset without limit.
