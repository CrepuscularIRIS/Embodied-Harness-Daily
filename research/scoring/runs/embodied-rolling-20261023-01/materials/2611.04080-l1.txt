# FEIJOA: Task-Driven Grounding and Execution for Mobile Manipulation

## Abstract
A mobile manipulator asked to "put the toys away in the toy box" must decide which objects are toys and which container the user means, then find base poses, grasps, and placements it can execute. Because a scene representation is built before the instruction is known, it may lack the attributes, affordances, or concepts needed to resolve the task. We present FEIJOA, a language-model agent that grounds the instruction at test time. It queries a grounding tool over a posed RGB-D scan, inspects the returned candidates, and refines its queries until they resolve the instruction. An embodiment-aware harness checks each skill's preconditions, samples base poses from which the target is reachable, and verifies the skill's effect from observations before and after execution. On 103 open-ended grounding queries, FEIJOA resolves 94.2% exactly, compared with 68.0% for the best prebuilt representation. Over 50 real-world trials on Spot, it completes 35 tasks; 17 of these successes follow recovery from a failed tool call or verification check. Of the 15 failed trials, 13 were caused by the robot's physical skills, and only 2 by grounding or the agent's reasoning. Project website: https://williamshen-nz.github.io/feijoa/.

## 1 Introduction
Robots operating in homes and offices must execute long-horizon tasks from open-ended natural language instructions. Consider asking a robot to “Clean up the room so the plush toys are all on the same table”. To complete this task, the robot must identify all the plush toys among everything else in the room, determine which table the user likely wants the toys placed on (one table already has four plush toys on it), navigate to base poses from which it can grasp and stably place the toys onto the table, and monitor its progress and recover from failures in execution. More generally, this requires open-ended grounding that depends on the task, the state of the environment, and common-sense reasoning. Acting on what is grounded requires finding base poses, grasps, and placements that are collision-free and feasible for the robot’s embodiment. Many existing approaches construct task-agnostic semantic scene representations before the instruction is known. These include open-vocabulary 3D object maps [ 1 ] , 3D scene graphs encoding spatial and semantic relationships between objects [ 2 , 3 , 4 , 5 ] , and 3D feature fields [ 6 , 7 , 8 ] . These representations make large environments efficient to index, since the expensive perception is done once, before any query. However, they reduce the scene to a collection of embeddings or captions, and are therefore incomplete with respect to any specific instruction: they may lack the fine-grained attributes, affordances, and concepts it requires (e.g., “most colorful object”, “plush toy with a bow tie”, “cleanest table with shelves above it”). We argue that for open-ended mobile manipulation, grounding must be task-driven and computed against raw observations at test time : which objects to find, and what relationships to resolve between them, depend on the instruction. We introduce Feijoa , a language-model agent for long-horizon mobile manipulation that decides what to ground and how to act (Figure 2 ). The agent has access to tools that ground objects, update and mark off subgoals in its task plan, estimate the cost of navigating between objects, and execute robot skills such as navigation, picking, placing, pushing, and wiping. At each turn, the agent chooses among these tools based on the current observations and robot state, its task plan, and the history of its reasoning and tool results. Our embodiment-aware harness constructs this context for each turn, dispatches every tool call, and records its result for the agent’s next decision. For a robot skill, the harness also checks feasibility before execution and verifies the effects afterwards. We evaluate Feijoa ’s grounding performance, ablate key design decisions in the harness, and deploy it in the real world on a Spot quadruped with an arm and an RB-Y1 bimanual humanoid with a wheeled base. Over 103 grounding queries that reference objects by category, attribute, spatial relation, membership in a set, or that require reasoning beyond appearance (e.g., negation, affordance, comparison), Feijoa finds every target object with no false positives on 94.2% of them. Feijoa significantly outperforms the best baseline, a text-captioned 3D scene graph at 68.0%, and our grounding tool without the agent at 47.6%. We demonstrate that each design decision in our harness matters by ablating effect verification, feasibility-aware sampling, and cost estimation. Finally, we run 50 real-world trials on Spot over short, medium, and long horizon tasks, in which the agent made 1,045 tool calls in total and executed up to 12 manipulation skills per trial, excluding navigation. Feijoa succeeds on 35/50 trials, 17 of them after recovering from a failed tool call or verification check. Of the 15 failed trials, 13 were caused by the robot’s physical skills, and only 2 by grounding or the agent’s reasoning. Overall, we make three contributions: (1) task-driven grounding, in which a language-model agent decides what and how to query our grounding tool and judges its results against the instruction; (2) an embodiment-aware agent harness that checks a skill’s preconditions and samples feasible parameters before execution, and verifies the effects afterwards; and (3) 50 real-world mobile manipulation trials on Spot with an analysis of how the agent recovers from failed tool calls and where the system fails.

## 3 Problem Formulation And Approach
3.1 Problem Definition We consider a mobile manipulator tasked with executing a natural-language instruction \ell in a previously scanned workspace. The agent is given an initial posed RGB-D recording \mathcal{D}_{0}=\{(I_{i},D_{i},K_{i},T_{i})\}_{i=1}^{N} , which serves as its Observation Memory , where I_{i} and D_{i} are the RGB image and depth map, K_{i} denotes the camera intrinsics, and T_{i}\in SE(3) maps camera coordinates into a common world frame. The robot is localized in this frame. Let e denote the robot embodiment and \mathcal{K}_{e} its library of parameterized skills, whose applicability depends on the robot’s kinematics and footprint relative to the scene’s geometry. During execution, the agent can acquire fresh observations o_{t} and access robot measurements r_{t} , including its current pose and holding state. We assume that the environment changes only through the robot’s actions; consequently, the initial recording provides prior observations that must be updated as execution proceeds. The instruction does not explicitly identify the corresponding objects in the scene or specify how the robot should physically interact with them and must be inferred from the instruction and available observations. The objective is to select perception queries and parameterized skills that accomplish \ell while respecting the embodiment’s physical constraints, minimizing expected travel cost. We denote successful completion by \operatorname{Sat}(s_{T},\ell)=1 , where s_{T} is the final physical state and \operatorname{Sat} expresses whether that state satisfies the instruction \ell . We limit execution to H interaction steps and a monetary inference budget C_{\max} . \operatorname{Sat} is not available to the agent as an executable goal test. 3.2 Working Context, Tools, and Decision Loop Feijoa agent : We address this problem through Feijoa , a history-conditioned agent comprising an off-the-shelf language model ( LLM ) and a robotics harness. We use Gemini-3.8-Flash with medium reasoning effort as the LLM . The LLM performs high-level reasoning and selects tool calls and their arguments from a working context \mathcal{W}_{t} . We build the robotics harness as a closed-loop orchestrator around this LLM , that constructs this context, maintains the task plan, exposes the tools that LLM can invoke, and coordinates tool execution, and feedback for subsequent decisions. We provide a tool library \mathcal{T}=\{\tau_{1},\ldots,\tau_{M}\} , consisting of grounding, perception, planning, and robot tools where each tool has a description and an argument schema. For grounding, find_objects returns object hypotheses matching language queries over \mathcal{D}_{0} . The perception tools observe and fetch_frames acquire fresh robot-camera images and retrieve previously stored images by frame identifier, respectively. For planning, estimate_cost compares estimated navigation costs for different visit orders proposed by the LLM , and update_plan revises the task plan. The ask_human tool waits for operator input and returns it as tool feedback; done and fail declare completion or failure.
