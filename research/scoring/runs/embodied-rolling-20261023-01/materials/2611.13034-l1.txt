# RoboACE: Adversarial Co-Evolution for Robot Self-Improvement

## Abstract
Robot agents can improve reusable skills, planning procedures, and recovery strategies from execution feedback, yet a fixed practice source leaves the search for new weaknesses unchanged. Useful practice depends on the agent's current capabilities, so the procedure that chooses practice must also be revisable. We present RoboACE (Robot Adversarial Co-Evolution), a framework that jointly evolves curriculum and execution harnesses around frozen foundation models. The curriculum harness uses accumulated capability evidence to propose informative challenges, while the execution harness responds with reusable revisions that expand execution capabilities. Alternating updates hold one side fixed as the other changes, and admitted challenges form fixed snapshots for comparing execution revisions. Starting from a compact set of LIBERO practice conditions, the resulting frozen deployment outperforms the evaluated controllers and agent systems across four LIBERO-family panels. On LIBERO-PRO, it reaches 74.0% success, exceeding the initial deployment by 15.0 percentage points and direct execution by its VLA controller by 13.5 points. Case studies document changes to evidence-guided practice selection, drawer-skill grounding, and controller intervention.

## 1 Introduction
Robot agents increasingly improve their own software through interaction: RoboRSI refines reusable skills, Zetta develops critics and recovery skills, and DynaHarness revises interfaces between semantic decisions and physical execution [ 33 , 5 , 3 ] . Together with RAX, which turns exploration feedback into reusable programs, these systems make execution procedures revisable [ 11 ] . An equally important choice is what the agent practices next, because a fixed source leaves unprobed weaknesses outside the feedback driving revision. Improving execution alone leaves this choice unchanged. Useful practice changes as an agent’s capabilities develop. A drawer skill that succeeds alone can still fail when composed with object placement, so practice must probe the composition as well as its individual steps. Selecting such practice requires interpreting prior outcomes, identifying prerequisites, and retaining conditions that reveal regressions. Automatic curricula already connect practice selection with skill accumulation [ 28 ] , but the selection procedure itself must also adapt as failures are resolved and new interactions emerge. Earlier rules for finding informative challenges can then become inadequate. This motivates a robot self-improvement loop that revises how it chooses practice alongside how it executes tasks. We introduce RoboACE (Robot Adversarial Co-Evolution), in which a curriculum harness and an execution harness evolve through an adversarial interaction (Figure 1 ). A harness contains the prompts, skills, tools, interfaces, and agent-readable memory that organize behavior around frozen foundation models. The curriculum side uses prior capability evidence to expose weaknesses in the current execution harness. The execution side responds with reusable revisions that expand execution capabilities, and its changing capabilities redirect the curriculum’s search. Independent agents make runtime decisions on each side, while external optimizers use the resulting evidence to install revisions for future runs. Adversarial challenge generation requires a stable reference for judging progress, so RoboACE alternates the two updates. With execution fixed, the curriculum side revises its procedures and proposes practice; admission checks validity and consistency before fixing a comparison snapshot. The execution side then evaluates candidate revisions on that snapshot, and consolidated outcomes inform the next curriculum update. This order separates challenge selection from the response it elicits, while an infrequently invoked Strategic Advisor reviews longer histories to reconsider repetitive or stalled revision directions. RoboACE brings together software self-improvement and evolving curricula through persistent revisions to both harnesses. RPG constructs practice from offline data and refines execution on the resulting fixed task set [ 32 ] ; our curriculum side also revises the procedures that select and construct subsequent practice. POET evolves environments together with their solutions [ 30 , 31 ] ; our implementation instead adapts the software that organizes challenge production and robot execution around frozen models. The changing task library is an output of curriculum-harness evolution, alongside the execution revisions it prompts. We instantiate this loop in simulated manipulation, beginning with a compact set of LIBERO practice conditions and evaluating frozen deployments on LIBERO, LIBERO-Plus, LIBERO-PRO, and LIBERO-X. The final deployment outperforms the evaluated systems on all four panels (Table 2 ). On LIBERO-PRO, it improves over the initial deployment by 15.0 percentage points and over direct execution by the same VLA controller by 13.5 points. Case studies show how evidence-reading guidance changes independent practice selection and how execution revisions clarify skill grounding and controller handoffs. Together, the framework and empirical study establish a concrete implementation of robot self-improvement in which both the practice-selection procedure and the execution software remain open to revision.

## 3 Adversarial Co-Evolution of Robot Harnesses
3.1 Framework Overview RoboACE takes prior capability evidence and the current pair of harnesses as input and returns revised harnesses together with evidence for the next round. The curriculum harness guides practice selection and construction; the execution harness organizes planning, code skills, and pretrained control. Each contains reusable prompts, skills, tools, interfaces, and agent-readable memory. All foundation-model weights remain frozen. Figure 2 shows how the two sides exchange evidence while updating in alternating phases. Each side separates runtime decisions from persistent revision. An independent agent runs its harness to propose practice or attempt a task. An external optimizer examines the resulting evidence, proposes changes, and tests them through further independent runs. We call the accepted harness version Stable and a proposed revision Candidate . A phase can retain its incoming Stable version, and its revision history records the tests and the reasons for adoption or rejection. The Strategic Advisor can review evidence across multiple local updates without taking over these decisions. In round k , the curriculum side receives the prior Capability Profile P_{k} and a fixed execution deployment. Its admitted proposals and the internal benchmark form a fixed task snapshot \mathcal{T}_{k} . The execution side first measures its incoming deployment on this snapshot, then tests revisions and selects a deployment. Consolidated execution evidence yields P_{k+1} . This ordering separates the curriculum’s prediction of useful practice from the difficulty and response measured afterward. Appendix A specifies the operational protocol. 3.2 Phase 1: Evolving the Curriculum Harness The curriculum must choose conditions that reveal actionable gaps in the current execution capability. Its agent reads P_{k} , which summarizes demonstrated abilities, applicable lessons, unresolved gaps, and uncertainty. Using this profile, task statistics, and descriptions of available tasks or assets, the agent retains, replaces, or adds practice conditions. Selection balances new challenges with prerequisites and familiar conditions that can expose regressions; increasing difficulty alone is not the objective. The curriculum optimizer revises how the agent makes these choices. It tests whether a candidate harness supports better use of evidence, maintains coverage, and recovers from failed retrieval or construction. The revised assets persist across future curriculum-agent runs, whose practice choices remain independent.
