# FastHarness: Experience-Driven Review Scheduling for Vision-Language-Action Policies

## Abstract
Agentic robot systems combine language-model reasoning with robot policies to monitor execution and recover from failures. However, reviewing every action chunk incurs substantial overhead, even in familiar situations. We introduce FastHarness, an experience-driven execution harness that adaptively schedules GPT-6 Astra supervision of a π0.5 policy. A fast path uses stage memory and reviewed outcomes to reduce review frequency as experience accumulates, while a complementary recovery path focuses supervision on correcting errors. Once recovery is verified, routine execution resumes, with failure experience retained to guide future interventions. The policy remains frozen and generates fresh actions from current observations. Across four simulated manipulation tasks, reviewer token use decreases by an average of 57.2% per task from the first evaluated episode to the mean of the final five episodes. Mean episode time decreases from 85.5 to 52.0 minutes over the same interval. On the same tasks, mean success increases from 80% for GPT-as-Policy (π0.5 + GPT-6 Astra) to 97.19% with FastHarness. These results highlight adaptive supervision as a practical route to more efficient agentic robotics without additional model training.

## 1 Introduction
Agentic robot systems ( Zhang et al., 2026 ; Fu et al., 2026 ; Lu et al., 2026 ; Shi et al., 2025 ) combine learned policies with language-model reasoning to monitor execution and recover from errors. A vision-language-action (VLA) policy ( Kim et al., 2024 ; Black et al., 2024 ; Lin et al., 2025 ; Lin et al., 2026c ; Lin et al., 2026a ; Brohan et al., 2023 ; Lin et al., 2026b ) maps observations and instructions to actions, while a language model uses execution feedback to assess progress and guide corrections ( Huang et al., 2022 ) . GPT-as-Policy follows this approach by pairing \pi_{0.5} ( Physical Intelligence et al., 2025 ) with GPT-6 Astra ( Su et al., 2026 ) . An execution harness coordinates the two models, determining when to request a review and how the resulting feedback affects subsequent actions. Frequent model calls, however, can make execution slow and costly. Reviewing every action chunk repeats this overhead even in task stages that the policy has already completed reliably. Errors require a different response: a missed grasp or dropped object may need several rounds of correction before execution can continue. Repeated task execution provides evidence for distinguishing these situations. The challenge is to use that evidence to reduce redundant review while retaining the supervision needed for recovery. We introduce FastHarness, an experience-driven harness that uses reviewed outcomes to decide when model supervision is needed (Figure 1 ). Repeatedly successful stages can proceed with less frequent review, while remembered failures prompt closer inspection when similar situations recur. The harness updates its memory and review schedule as experience accumulates. The \pi_{0.5} policy remains fixed and generates each action chunk from the current observation. FastHarness implements this adaptation through two complementary paths (Figure 2 ). During routine execution, the fast path uses the current task stage and its reviewed history to set the review frequency. When an error is detected, the recovery path guides local repair under continued review. After the reviewer verifies recovery, the harness resumes ordinary scheduling. It retains the failure record to guide future interventions. We evaluate FastHarness on four simulated manipulation tasks, examining both execution efficiency and task success. Across repeated runs, reviewer token use decreases by an average of 57.2% per task, and mean episode time falls from 85.5 to 52.0 minutes. These comparisons use the first evaluated episode and the mean of the final five episodes. On these same tasks, mean success increases from 80% for the baseline to 97.19% with FastHarness. Execution traces illustrate how the harness adjusts review frequency and resumes routine execution after recovery.

## 3 Problem Setting
We consider a robot executing a manipulation task specified by a language instruction. At each decision step, a pretrained vision-language-action (VLA) policy receives the current observation and proposes an action chunk comprising multiple control steps. A separate model-based reviewer can assess recent execution and the proposed actions, then approve the proposal or provide corrective feedback. The task is executed over a sequence of episodes with varying scene layouts. Within each episode, the harness maintains a history of observations, actions, and feedback. Across episodes, it retains task-specific experience that can inform later decisions. We refer to episodes connected by this persistent memory as a memory chain . The VLA policy weights remain fixed throughout the chain; adaptation occurs in the harness’s memory and supervision schedule. The harness determines when to request review and how to incorporate feedback into subsequent execution, including error recovery. We study how accumulated task experience can reduce model-review overhead while maintaining task performance. Task success is defined by the environment’s completion criterion.

## 4 FastHarness
FastHarness augments the GPT-as-Policy execution loop with a scheduler that uses task memory to coordinate \pi_{0.5} and GPT-6 Astra (Figure 2 ). For each new observation, the policy proposes an action chunk and the scheduler decides whether it requires review. The fast path adjusts this decision using stage-specific experience; the recovery path maintains review while a detected error is corrected. Reviewed outcomes update the memory used for subsequent decisions. 4.1 Experience-Driven Fast Path Stage recognition and outcome memory. The reviewer assigns stage labels, such as approaching, grasping, and placing, during reviewed execution. FastHarness represents observations using downsampled RGB views and proprioceptive state, and stores examples under these labels. It matches each new observation to the nearest stored example for each stage; a distant or ambiguous match triggers review. Stage statistics use only explicit success or failure judgments for the immediately preceding ordinary policy transition, attributed to its pre-action stage. Earlier chunks between reviews receive no individual labels, and corrective or recovery actions are excluded from these counts. Experience-driven review scheduling. For each stage, the scheduler computes a conservative score from reviewed success and failure counts. It combines this score with the amount of reviewed experience to set the interval between reviews. Limited evidence, or insufficient consecutive successes after an error, keeps the interval at one chunk. Higher scores and more reviewed samples permit longer intervals. Unknown or ambiguous contexts, uncertainty from the previous review, execution alerts, and proximity to remembered errors override this interval and trigger review. Stage-transition checks, random audits, and a control-step limit between reviews provide additional review triggers. Appendix A specifies the matching rule, score, interval function, and trigger priority. Observation-conditioned execution. When no review is required, the executor runs a prefix of the current policy proposal within the remaining control-step allowance since the last review. It then obtains a new observation and proposal before the next scheduling decision. Longer review intervals therefore retain observation-conditioned control between chunks; stored trajectories are not replayed. 4.2 Error Recovery Path Detecting errors and repairing locally. A reviewed execution error or intent mismatch activates the recovery path. Every action chunk is reviewed while recovery is active. The reviewer first guides local corrections from the current state, such as re-approaching and re-grasping a dropped object. Recovering toward verified waypoints. If local repair does not resolve the fault, the harness can select a waypoint verified earlier in the episode. It first considers the most recent eligible waypoint and can select an earlier one if needed. The policy generates new actions toward the selected goal in the current environment. Selecting a waypoint does not reset the environment. Verifying recovery and resuming execution. Ordinary scheduling resumes only after the reviewer confirms that the fault has been resolved. For waypoint-based recovery, verifying the return goal is followed by a separate assessment of the original fault. Recovery completion clears the active recovery state while retaining the error record and its recovery evidence. Later observations near that error still require review, even when the stage’s overall success record has improved.
