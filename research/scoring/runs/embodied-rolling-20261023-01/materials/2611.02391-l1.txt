# Late Autumn: LLM Agents Specialize a General Multi-Robot Planner for One Warehouse

## Abstract
No algorithm is best on all problems, but a real warehouse is a narrow problem: its layout and processes rarely change. Operators still run one general multi-robot planner at many sites, because experts cannot tune it for each one. In this work, which we call Late Autumn, we explore whether LLM coding agents running autonomous research can specialize a general planner for one site, trading generality for throughput, much as post-training adapts a pretrained LLM to one task. We study six campaigns on a lifelong planner that combines task assignment with multi-agent path finding, on a floor modeled on an existing automated warehouse. We find that (1) the agents raise throughput by 22--60%, and the gains hold on unseen seeds; (2) they rediscover known MAPF mechanisms, such as corridor-exit priorities, local guidance, and rollouts, and independent campaigns find the same bottleneck; (3) the gains largely carry over to another layout, a larger fleet, and other service times, shrink with a smaller fleet, and mostly vanish under an outbound-heavy demand mix; and (4) each final patch (0.7k--2.4k lines) is a chain of scored commits with a median step of 27 lines, so experts can review it, and review finds problems that the score misses; some patches multiply planner compute by over 100x. LLM agents can therefore turn each site's bias into extra throughput at little engineering cost, with reviewable patches; we expect experts to shift toward designing insightful metrics and fast simulators that mirror the real problem.

## 1 Introduction
Automated warehouses move goods with fleets of robots that shuttle cases between storage aisles and stations. Commercial systems take many forms (Figure 1 ): drive units that carry shelves to pickers (Amazon Robotics, Geek+), bots that carry cases through multi-level aisles (Symbotic), robots on a grid above stacked bins (AutoStore), rack-climbing tote robots (Hai Robotics), and robots that work beside human pickers (Locus Robotics). The coordination layer must repeatedly assign tasks to robots and plan collision-free paths for all of them, a lifelong variant of Multi-Agent Path Finding (MAPF) with target assignment ( Ma et al., 2017 ; Li et al., 2021 ; Ma and Koenig, 2016 ) . MAPF is NP-hard to solve optimally ( Yu and LaValle, 2013 ) , so large fleets call for fast suboptimal planners such as PIBT ( Okumura et al., 2022 ) and LaCAM ( Okumura, 2023b ) . We use a lifelong version of ITA-LaCAM ( Tang et al., 2026 ) , which couples target assignment with LaCAM search. As a concrete example, we model the floor of one existing automated warehouse; since MAPF models any AGV warehouse as a graph with tasks, the approach is not tied to it. This planner is a general algorithm, designed for a broad class of layouts and workloads. By the No Free Lunch theorems, averaged over all possible problems, every search algorithm performs equally well ( Wolpert and Macready, 1997 ) . Real sites are far from this average: warehouses differ in aisle geometry, fleet size, carry capacity, demand mix, and service times, but each one runs the same layout and largely fixed processes every day. A planner can therefore trade generality that one site never needs for throughput, much as post-training specializes a pretrained LLM. Until now, only experts could exploit this bias, by inspecting traces and changing cost or priority rules, and no company can do this for its growing number of sites. An agent that can would give each site extra throughput at almost no engineering cost. LLM-based coding agents now perform parts of this loop ( Novikov et al., 2025 ; Qu et al., 2026 ) , but most of this evidence comes from short programs with cheap, deterministic scores. A warehouse planner differs in three ways. First, the agent edits a complete planner (assignment, search, and simulation) rather than a single heuristic function. Second, the score comes from a stochastic simulation in which many changes are smaller than the noise, so an agent can “improve” by chance. Third, a change reaches physical robots only after an engineer understands it and trusts it. We therefore ask: RQ1 After autonomous research on one site configuration, does the planner’s throughput really improve? RQ2 What methods do the agents propose? RQ3 Are these methods site-specific, or do they work for other warehouse configurations? RQ4 How large is each improving change, and can an expert review it to confirm, from first principles, that it is correct? In this work, which we call Late Autumn, we explore this idea with an existing auto-research system and answer these questions with a case study. An agent receives the planner repository and a task contract that fixes one site configuration. It may change any planner logic, but it is scored only on hidden seeds by an isolated host, and it must commit and evaluate every candidate. We ran six campaigns (three model families, three knowledge settings; 600 official evaluations), re-evaluated each best patch on fresh seeds and on seven held-out configurations, and analyzed every diff that raised the best score. Our results show that every campaign’s best patch beats the baseline on all 20 fresh seeds, by 22–63%, and that the patches keep a significant gain in 40 of 42 held-out configurations. Our contributions are: 1. A case study of agent-driven specialization of a lifelong MAPF planner to one site, run with hidden-seed scoring, a mandatory commit-and-evaluate lifecycle, and compute accounting. 2. Evidence that agents raise throughput by 22–60% ( RQ1 ). 3. A catalog of the discovered mechanisms ( RQ2 ), a transfer study ( RQ3 ), and a code-level analysis ( RQ4 ): improving steps are small (median 27 lines), so even the final patches can be reviewed commit by commit, and review finds problems that the score misses.

## 2 Problem Definition and Baseline
Lifelong TAPF with multi-carry robots. Let G=(V,E) be a 4-connected grid graph whose vertices are free cells; self-loops represent waiting. Agents I=\{1,\dots,N\} start at distinct vertices and each can carry at most K tasks. Tasks are released online; a task \tau=(s_{\tau},G_{\tau}) has a pickup vertex s_{\tau} and a goal set G_{\tau}\subseteq V , any vertex of which completes the delivery. Let x_{i}(t)\in V be the location of agent i at timestep t . A plan is valid if, for all agents i\neq j and timesteps t : 1) x_{i}(t{+}1){=}x_{i}(t) or (x_{i}(t),x_{i}(t{+}1))\in E ; 2) x_{i}(t)\neq x_{j}(t) (no vertex conflict); 3) agents never swap vertices (no edge conflict); and 4) agent i picks up \tau only by staying at s_{\tau} for d_{p} consecutive timesteps while it carries fewer than K tasks, and delivers \tau only by staying at some g\in G_{\tau} for d_{d} timesteps. The objective is throughput : tasks completed within horizon H , divided by H . Each planner call has a 1 s wall-clock limit. Baseline planner. Our planner, a lifelong version of ITA-LaCAM ( Tang et al., 2026 ) , replans after every pickup or delivery or when its plan runs out. A Hungarian matching assigns each agent one goal option (a pickup, a goal cell of a carried case, or a costly wait), costed by distance plus service time, with at most one agent per pickup or drop cell; as in ITA-CBS ( Tang et al., 2023 ) , the matching is repaired incrementally at each search node. LaCAM ( Okumura, 2023b ) with FOCAL node selection then generates configurations with PIBT ( Okumura et al., 2022 ) until some agent completes a service. The planner has 9.0k lines of C++ and needs 4.8 ms per call at the tuned site (§ 4 ): its anytime refinement exits after the first solution (the stopping test compares quantities on different scales), so over 99% of the budget is unused. It reaches a hidden-seed throughput of 1.23 (pseudo-code in Appendix A ).

## 4 Auto-Research Setup
In this section, we describe the auto-research setup: the agent’s tools, the task contract it must follow, and how we re-evaluate its results. We use CORAL ( Qu et al., 2026 ) to run one autonomous coding agent per campaign in its own git worktree (Figure 2 a). The agent can read and edit all code, build, test, inspect traces, and request evaluations. A natural-language task contract (Appendix C ) sets the rules below. Site and workload. The site the agents tune (Figure 2 b) follows one existing warehouse floor: a 35{\times}39 grid with 691 free cells, 19 one-wide storage aisles of 20 cells, and 8 one-wide station lanes; a wall splits it into two halves joined by a single cell.
