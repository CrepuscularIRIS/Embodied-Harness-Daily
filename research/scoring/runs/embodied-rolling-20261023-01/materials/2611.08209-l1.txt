# RoboARCade: Benchmarking Agentic Robot Control

## Abstract
Improvements in multi-modal capabilities have enabled agents to act directly as robot policies, a setting we refer to as agentic robot control (ARC). We introduce RoboARCade, a benchmark of long-horizon manipulation tasks across three embodiments designed to test in-context adaptation, memory, and reasoning for precise control. The tasks build on existing open-source benchmarks, which we make harder by widening the range of initial conditions. RoboARCade is easy to use and extend: all tasks run on a single simulation backend, MuJoCo, each task is a self-contained data pack, and agents connect through interchangeable interfaces, so new tasks, agents, and interfaces can be added independently. The benchmark separates leading agents: GPT-6 Astra achieves 49.8% compared with 43.6% for Claude Fable 5.1, leaving substantial room for improvement. Comparing two interfaces, we find that a richer visual interface adds only 1.5 to 6.8 points at 1.7 to 2.3 times the cost. Failures stem mostly from choosing a poor manipulation strategy or executing a good one imprecisely, rarely from misunderstanding the scene, and agents incorrectly claim success on 24% to 39% of attempted subtasks. Agents can also improve without human input: one successful demonstration in context raises Astra's score from 53.5% to 73.0% on a five-task subset, and a prompt the agent writes and revises itself reaches 72.0%. Code, videos and full traces are available at roboarcade.org.

## 1 Introduction
Recently, foundation models (FM) have begun controlling robots through several approaches: training Vision-Language-Action (VLA) models ( Zitkovich and others, 2023 ; Kim et al., 2025 ; Black et al., 2025 ) , integrating models into hierarchical control systems ( Ichter et al., 2023 ; Huang et al., 2023 ; Belkhale et al., 2024 ; Shi et al., 2025 ; Hu et al., 2026b ) , and generating executable perception and control code, as in Code-as-Policies (CaP) ( Liang et al., 2023 ) , more recently inside coding-agent harnesses that write programs ( Fu et al., 2026 ) or computation graphs ( Chen et al., 2026a ) . Frontier multimodal FMs now allow a fourth approach: the agent observes the world directly through pixels and controls robots itself with no learned policy or program in between. We refer to this setting as agentic robot control (ARC). Evaluations of ARC disagree about how well it works. Commanding end-effector motions directly, the models in Berman et al. (2026) completed at most 5.5% of LIBERO tasks, or 32% of a ten-task subset with a cursor tool. Through a 3D visual interface, VIA ( Hu et al., 2026a ) reached 96.7% on three LIBERO-Goal tasks. On the 42 tasks of RoboDojo, GPT-6 Astra reached 22.5% ( Zhang et al., 2026 ) . Each study used its own tasks, models, and interface, so these results cannot be compared with one another. RoboARCade provides a common benchmark built for ARC that is not saturated: the VIA interface that nearly saturates LIBERO-Goal reaches 43.6% subtask success here. RoboARCade brings together custom and preexisting tasks and assets in a unified codebase, spanning single-arm and bimanual manipulation, assembly, physical puzzles, and high-precision biolab-inspired procedures. Fig. 1 shows a subset of the task suite. For tasks adapted from prior work, we increase difficulty by broadening the range of initial conditions and improve visual fidelity through Blender rendering. All tasks run on a single simulation backend, MuJoCo, and each is a self-contained data pack, so new tasks, agents, and interfaces can be added independently. Using this suite, we evaluate two families of frontier agents, Codex and Claude Code, and compare their performance and efficiency across two control interfaces. The first, multi-view RGBD , provides color and depth images from multiple cameras and sends end-effector commands directly to the controller. The second, from Visual Interface Agent (VIA) ( Hu et al., 2026a ) , provides an interactive 3D virtual workspace in which agents can adjust a virtual target gripper using visual feedback before commanding the robot to move. The results reveal substantial differences across agents and interfaces: with VIA, GPT-5.6 Sol achieves a success rate of 14.0%, compared with 43.6% for Claude Fable 5.1 and 49.8% for GPT-6 Astra. For Fable, VIA improves success over multi-view RGBD by 6.8 percentage points but increases the average cost per trial by 67%. Even the strongest combination, Astra with VIA, succeeds on fewer than half of trials, leaving substantial room for improvement in both agents and control interfaces. Scene understanding is rarely the obstacle: only 2 to 6% of attempted subtasks end there. Failures come instead from choosing a poor manipulation strategy or executing a good one imprecisely. Retries help with both: Astra’s subtask success rises from 34% on the first try to 50% after five or more. Agents also misjudge their own progress, incorrectly claiming success on 24% (Astra) to 39% (Claude Opus 5) of attempted subtasks. We further evaluate in-context learning from successful rollouts and autonomous text-only prompt optimization on a subset of five tasks. In prompt optimization, agents revise their instructions using rollout feedback. GPT-6 Astra’s mean rubric score increases from 53.5% to 73.0% with in-context learning and 72.0% after two rounds of prompt optimization. Despite these gains, precision errors and incorrect claims of success persist.

## 3 RoboARCade
In this section, we first describe the benchmark infrastructure in Sec. 3.1 , then its features in Sec. 3.2 , and finally our evaluation of autonomous improvement in Sec. 3.3 . 3.1 Benchmark Infrastructure The benchmark has three components: a task suite, a simulation environment, and an agent interface. For each evaluation, we initialize the selected task and seed in the simulation environment and create an agent sandbox. The agent cannot access privileged state, such as object poses, from the sandbox. It acts in the simulator and receives observations through the selected interface. Simulation Environment. Each task specifies a MuJoCo scene, instructions, robot and camera configurations, randomized initial conditions, and success predicates. For each trial, we enforce a timeout budget for each trial. The agent uses a selected interface to observe the scene and command the robot. Its commands are converted into absolute end-effector poses and then into joint-position targets for execution in MuJoCo. After each action, persistent Blender workers render high-fidelity RGB images. Interactions and videos are recorded for offline analysis, while success predicates outside the agent sandbox determine rubric scores. Agent Interfaces. VIA ( Hu et al., 2026a ) is a browser-based 3D interface with a fused point cloud, selectable camera views, and a virtual target gripper. The agent uses structured tools to select image locations, adjust the target gripper’s position and orientation, preview reachability, and execute waypoints. Multi-view RGBD instead provides calibrated color images and aligned, quantized depth images, together with camera intrinsics, extrinsics, and end-effector proprioception. The agent specifies Cartesian translation and rotation increments and gripper commands, which execute immediately and return updated observations. Both interfaces use the same simulation and motion controller. They differ in how they present spatial information and specify actions. Agent Sandbox. The agent receives task instructions, interface documentation, camera observations, and gripper readouts. It cannot access privileged simulator state, task assets, success predicates, or grading results, and it cannot modify the interface or benchmark files. Network access is limited to the services needed to use the interface and model provider. These restrictions keep task outcomes and grading information outside the agent’s view. Task Curation. We curate 22 tasks spanning precise manipulation, memory, planning, and bimanual control. For example, the Shell Game requires tracking objects through swaps, Lights Out requires planning across 42 buttons, and Strongbox and Pack Tools require completing many sequential subtasks. Furthermore, we include tasks that test precise placement under tight tolerances. Fig. 1 visualizes a subset of the full benchmark. The benchmark combines assets and tasks from existing open-source simulation benchmarks in addition to original assets.
