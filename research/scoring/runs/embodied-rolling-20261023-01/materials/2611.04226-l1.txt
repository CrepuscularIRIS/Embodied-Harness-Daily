# DiMuRe: Diagnosis-Guided Multilevel Recovery for Robotic Task Execution

## Abstract
Disturbances can invalidate the conditions required by a robot's next action even when much of its task program remains useful. A recovery system must therefore choose a response suited to the current state. We present DiMuRe (diagnosis-guided multilevel recovery), a framework for robot-use agents that uses phase-specific evidence and method preconditions to select program reuse or predefined recovery skills, including bounded vision-language-action (VLA) grasping. After the original program exits, a multimodal large language model (MLLM) can generate corrective code from images and execution feedback. Local verification checks the outcome of each recovery attempt. We also introduce LIBERO-Disturb, a benchmark for robustness and recovery under mid-execution disturbances, supporting program-based agents and VLA policies. On 801 scheduled disturbed Encore development cases, Local DiMuRe (program reuse and recovery skills) achieves 77.65% complete-task success, compared with 58.68% for the original program under the same physical-step allowance. Full DiMuRe achieves 81.90% with terminal replanning, an additional step allowance, and early handoff. Local DiMuRe also uses fewer physical steps per scheduled episode than the original program.

## I Introduction
When a target object moves during manipulation, a previously valid grasp command may fail even though much of the task program remains useful. Robot-use agents express perception, motion, and feedback through executable programs [ 12 , 21 ] , which can already include checks and retries. Recovery therefore requires determining which parts of the existing behavior still apply. If the object has only shifted in position, translating a recorded grasp segment may suffice. If the grasp assumptions no longer hold, a different recovery procedure may be needed. Each recovery option has limits. Program reuse preserves task-specific motions but depends on the available segments and how they can be adapted. Predefined recovery skills, including bounded vision-language-action (VLA) grasping, handle particular failures when their preconditions are met. A multimodal large language model (MLLM) can compose new action sequences from visual observations and execution feedback, at the cost of additional inference and verification. Choosing among these options requires more than a failure alarm. The system needs evidence that a response is applicable and must then check whether it restores the state needed to continue the task. Obtaining this evidence also takes time, so the decision must account for the cost of further sensing and reasoning. To study these choices, an evaluation must introduce controlled disturbances during execution. Specifying a disturbance does not guarantee that it was applied, had its intended physical effect, or prevented task completion. Recording these outcomes separately makes it possible to assess both the original program’s resilience and the benefit of added recovery. To address these challenges, we make two contributions: • DiMuRe uses phase-specific diagnostic evidence to select among program reuse, predefined recovery skills, and MLLM-assisted replanning. It checks each method’s preconditions and verifies the result of recovery before deciding how to continue. • LIBERO-Disturb is a benchmark for mid-execution disturbance robustness and recovery in robotic manipulation. It separates disturbance injection and task evaluation from the tested system, supporting both program-based robot-use agents and VLA policies. The central hypothesis is that different recovery capabilities handle different failure conditions. The evaluation tests whether combining them improves task success while preserving the original program’s successful outcomes. It also measures execution time and model use. ## III Problem Setting
The agent executes an original task program \mathsf{P}_{\mathrm{orig}} . Its source remains fixed, including its original feedback and retry logic. Disturbances may displace a target, break a grasp, or move a receiving region. The task goal remains unchanged, but subsequent commands may fail unless the affected conditions are restored. Additional recovery is needed when the original program cannot handle these changes. Given the task instruction, program context, sensor observations, and action feedback, the problem is to determine when recovery is needed, which available method applies, and whether its outcome allows the task to continue. The objective is to complete the original task within a declared total physical-step budget B , reusing existing behavior where possible and choosing additional recovery from the available evidence and resources. Online decisions do not use hidden simulator state, disturbance labels, or the native success predicate. The native evaluator assesses complete-task success independently.

## IV Layered Diagnosis and Multilevel Recovery
Figure 2 summarizes how phase-specific diagnosis connects original-program execution with local recovery and terminal MLLM-assisted replanning. IV-A Program Interface and Observations An execution monitor intercepts motion and gripper calls, records grasp and placement segments, and matches objects and receiving regions named in the program to sensor observations. In the Encore integration [ 11 ] , the monitor uses RGB-D geometry, robot state, and gripper state to track object identity and motion and to assess grasping and release. It evaluates relations expressed in the task instruction using measured geometry. The index t denotes an observation or decision event, which need not advance physical execution. Positions are expressed in the robot base frame, and all lengths are in meters. A hat denotes an estimate obtained from RGB-D geometry. IV-B Layered Diagnosis: When to Intervene The diagnoser checks execution conditions for the current manipulation phase using robot and gripper state, measured object geometry, and task relations. It requests additional observations when missing geometry or poor visibility prevents a decision. The diagnostic record is d_{t}=\mathcal{D}(\phi_{t},\mathcal{E}_{t}). (1) Here \mathcal{D} is the rule-based diagnoser, \phi_{t}\in\{\text{grasp},\text{transport},\text{place},\text{verify}\} is the current phase, and \mathcal{E}_{t} contains robot state, measured object geometry, task relations, action feedback, prior verification results, and budget information. The output d_{t} contains a diagnostic code, rule-based confidence, a suggested response, and supporting evidence. Missing measurements are treated as unknown. The confidence is not a calibrated probability of success. During original-program execution, the monitor first checks the gripper opening, then compares object and tool motion to assess whether the object is attached to the gripper. Their displacement residual is e_{t}^{\mathrm{follow}}=\left\|(\hat{\mathbf{c}}_{t}-\hat{\mathbf{c}}_{\mathrm{ref}})-(\mathbf{p}_{t}-\mathbf{p}_{\mathrm{ref}})\right\|_{2}. (2) The vectors \hat{\mathbf{c}}_{t} and \mathbf{p}_{t} are the current estimated object center and measured end-effector position. Subscript \mathrm{ref} denotes the reference measurements stored for the current grasp check. The Euclidean norm \|\cdot\|_{2} measures the difference between the object and tool displacements. The test requires sufficient visible geometry and tool displacement \|\mathbf{p}_{t}-\mathbf{p}_{\mathrm{ref}}\|_{2}>\tau_{\mathrm{move}} , where \tau_{\mathrm{move}} is the minimum tool displacement required to evaluate attachment. A verified grasp additionally requires e_{t}^{\mathrm{follow}}<\tau_{\mathrm{follow}} and g_{\min}<g_{t}<g_{\max} , where \tau_{\mathrm{follow}} is the maximum accepted displacement residual, g_{t} is the measured gripper opening, and g_{\min} and g_{\max} are its lower and upper admissible bounds. These thresholds and measurements are lengths in meters. The monitor also requires evidence that the object is no longer supported. Insufficient motion or visibility leaves attachment unconfirmed. If the measurements suggest contact near the receiving region, the diagnoser requests release verification before classifying the object as held or slipped. After release, placement checks assess whether the object has detached from the gripper and is supported by the receiving region.
