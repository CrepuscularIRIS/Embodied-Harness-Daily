===ABSTRACT===
Large multimodal models can support long-horizon robot manipulation, but frequent model calls incur substantial latency and token costs. The central challenge is determining when agent assistance or intervention is needed and whether errors require correcting robot execution, subtask planning, or both. To address this problem, we propose RoC (Reasoning on Call), an efficient framework that coordinates a low-level policy and a high-level reasoning agent through an online task-state monitor. The monitor combines temporal visual observations with ordered interaction memory to jointly estimate progress within the active subtask and predict its successor. These predictions guide event-triggered agent review for coordinated execution repair and plan revision. Verified outcomes govern memory updates and subtask transitions, allowing routine execution to remain with the policy while reasoning focuses on decisions requiring additional assessment. On RMBench, RoC improves task success rate by 24.0 percentage points and reduces token consumption by 65.3% compared with the strongest agent-based baseline. It also outperforms the strongest policy-based baseline by 15.1 percentage points in task success rate. Real-world experiments further validate its effectiveness across three long-horizon manipulation tasks. Overall, RoC supports efficient agent intervention and coordinated recovery across execution and planning for long-horizon robot manipulation.

===INTRO===

Long-horizon robot manipulation requires both reliable execution and effective planning. A robot must carry out individual subtasks, assess their outcomes, and determine which goal to pursue next. Visuomotor policies, such as VLAs [ 9 ] and WAMs [ 22 ] , provide action execution capability, but successful long-horizon manipulation also requires coordinating these actions with task-level decisions. Recently, agentic robot control approaches such as GPT-as-Policy [ 18 ] and Harness VLA [ 25 ] introduce multimodal reasoning agents to interpret task context, coordinate subtasks, and guide recovery. However, repeated agent calls incur substantial token costs and inference latency [ 17 , 11 ] . These costs accumulate as the agent repeatedly processes visual observations and execution history. When execution must wait for its decisions, agent intervention becomes a bottleneck even during routine behavior that the policy can handle independently. The challenge is therefore to determine when agent intervention is needed and how it should guide execution repair and plan revision, without repeatedly querying the agent itself. To address this challenge, we propose RoC (Reasoning on Call), an efficient framework that coordinates a low-level policy and a reasoning agent through an online task-state monitor . The monitor integrates stage-aware visual context with ordered interaction memory to jointly estimate active subtask progress, predict transition requests, and propose next goals. Progress anomalies, transition requests, and critical contact events in candidate actions selectively trigger agent review. Using shared task and execution context, the agent can authorize continued policy execution, shorten or refine candidate actions, take over subtask execution, or revise the proposed next goal. Verified outcomes govern memory updates and subtask transitions. This design allows routine execution to remain with the policy while directing agent reasoning toward decisions that require further assessment or correction. We evaluate RoC on both simulated and real-world tasks, assessing task success and token consumption. On RMBench, RoC improves task success rate by 24.0 percentage points and reduces token consumption by 65.3% compared with the strongest agent-based baseline. It also outperforms the strongest policy-based baseline by 15.1 percentage points in task success rate. Three long-horizon tasks on the SO-ARM101 platform further demonstrate the effectiveness of RoC in real-world settings. To summarize, our main contributions are twofold: • We propose RoC, an efficient agentic robot control framework for long-horizon manipulation that couples monitor-triggered agent review with coordinated execution repair and plan revision. • We develop an online task-state monitor that serves as a plug-in module to guide selective agent intervention, reducing redundant agent calls and reasoning overhead.

## 3 Method
RoC follows a monitoring–execution–review loop. At initialization, the online task-state monitor proposes the first subtask from the task instruction and initial observation, using empty subtask and interaction-memory inputs. The reasoning agent confirms this proposal before policy execution begins. During execution, the monitor estimates the active subtask progress and predicts transition requests and next goals. Transition requests, progress anomalies, and critical contact events trigger agent review for coordinated execution repair and plan revision. Verified outcomes and approved transitions govern memory updates and task progression. We formulate the component interfaces in Sec. 3.1 , then describe the online task-state monitor in Sec. 3.2 and the agent intervention mechanism in Sec. 3.3 . 3.1 Problem Formulation Given a language instruction g specifying a task, the robot receives an RGB observation o_{t} and proprioceptive state q_{t} at global control step t . RoC maintains visual history \mathcal{H}_{t} (including o_{t} ), ordered interaction memory \mathcal{M}_{t} containing verified records, and an active subtask \ell_{k} . Here, k indexes subtask instances independently of t . The online task-state monitor estimates progress within the active subtask and proposes subtask transitions: (p_{t},s_{t},\widetilde{\ell}_{t})=F_{\phi}(g,\ell_{k},\mathcal{M}_{t},\mathcal{H}_{t}) (1) where p_{t}\in[0,1] is the progress estimate of \ell_{k} , s_{t} is the transition-request probability, and \widetilde{\ell}_{t} is a candidate successor or task-termination proposal. Progress estimates are used to detect execution anomalies, while s_{t} determines whether to request a transition. The candidate \widetilde{\ell}_{t} specifies the proposed next goal. The low-level policy proposes an action chunk at each control step: A_{t}\sim\pi_{\theta}(\cdot\mid\ell_{k},q_{t},\mathcal{H}_{t}^{\pi}) (2) where A_{t}=(a_{t,1},\ldots,a_{t,H}) and \mathcal{H}_{t}^{\pi} denotes the observations selected from \mathcal{H}_{t} for policy inputs. Before executing an initial segment of A_{t} , termed the execution prefix, RoC evaluates three triggers for agent review: progress anomalies, transition requests, and critical contact events in A_{t} . The corresponding triggering mechanism is defined in Sec. 3.3 . If no review is triggered, RoC executes the prefix and obtains new observations. Otherwise, it withholds the affected actions while the agent reviews the candidate actions and any requested subtask transition. 3.2 Progress Monitoring and Subtask Prediction Interaction Memory and Visual Context. The monitor conditions on g , \ell_{k} , \mathcal{M}_{t} , and observations selected from \mathcal{H}_{t} . Each entry in \mathcal{M}_{t} contains a subtask instruction, executed actions, an outcome description, and timestamps corresponding to supporting observations in \mathcal{H}_{t} . Records follow execution order, with repeated instructions retained as distinct subtask instances. Their generation and commitment are described in Sec. 3.3 . We select visual context from \mathcal{H}_{t} using stage-aware sampling. Sparse observations uniformly sampled from the initial time step to the start of the current subtask provide a persistent scene reference and historical context. Denser observations are uniformly sampled from the start of \ell_{k} to time t , capturing local execution changes. This balances historical coverage and local detail under a fixed visual input budget, while \mathcal{M}_{t} preserves interaction outcomes that sparse observations may miss, as illustrated in Figure 3 . Online Task-State Monitor. We initialize F_{\phi} from Robometer [ 12 ] , a general-purpose robotic reward model. Its pretraining combines progress supervision with trajectory comparisons involving successful, suboptimal, and failed executions, providing a pretrained basis for assessing execution progress. Visual observations sampled from \mathcal{H}_{t} , together with g , \ell_{k} , and the ordered subtask list recorded in \mathcal{M}_{t} , form a shared context for the monitor’s predictions. Specifically, learnable progress tokens and densely sampled observations are causally interleaved. The contextual hidden state of the current observation’s progress token feeds both the progress head and the transition-request head. The progress head predicts a categorical distribution \mathbf{p}_{t} over ten discrete progress values in [0,1] , whose expectation gives the scalar estimate p_{t} . This estimate describes the relative execution stage within \ell_{k} and is used for progress-anomaly detection. The transition-request head predicts s_{t} directly from the same contextual representation. Although the two heads share their underlying features, they have different supervision and control roles: p_{t} identifies abnormal progress patterns, while s_{t} requests a change of subtask. An autoregressive language generation branch proposes \widetilde{\ell}_{t} or task termination from the shared context. The request head therefore predicts whether a transition should be reviewed, while the generation branch specifies which subtask should follow. During execution, the generation branch is activated only when s_{t} exceeds the transition threshold; otherwise, successor generation is skipped. Progress and transition-request predictions are read from context positions preceding the successor text, preventing the target instruction from leaking into these predictions during training. Completion is verified by the reasoning agent during review, as described in Sec. 3.3 . Training Objective. Subtask transitions are temporally sparse, so uniform sampling yields far more training examples within subtasks than near their boundaries. This imbalance can make accurate transition timing difficult to learn.
