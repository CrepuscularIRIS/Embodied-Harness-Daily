# RoboDuo: Attempt, Check and Atomic Recovery through Code for Vision-Language-Action Models

## Abstract
Vision-Language-Action (VLA) models map a language instruction and the current observation directly to actions, without checking whether the instruction has been completed. For long-horizon tasks, a single failed step therefore goes unnoticed and leaves the whole task unfinished. Such failed episodes, however, often end with the task partially complete. Moreover, the unfinished steps are reusable atomic skills that recur across demonstrations. A failed attempt can thus be recovered by composing with atomic skills. We propose RoboDuo, a closed-loop dual-system framework that uses code as the interface between a coding agent and two VLAs. The agent writes a program that lets a full-task VLA attempt the whole task and checks whether it is complete; on failure, an atomic VLA finishes the remaining steps. Since the agent emits no actions and only decides which VLA for execution, RoboDuo wraps an existing full-task VLA without updating its weights. To train the atomic VLA and the coding agent with the completion-checking ability, we build LIBERO-Atomic, LIBERO-Code, and LIBERO-Judge from a single set of LIBERO demonstrations. RoboDuo consistently improves X-VLA and $π_{0.5}$ on LIBERO and LIBERO-PRO, with the largest gains on long-horizon tasks, and recovers failed rollouts of a frozen full-task VLA on a real robot.

## 1 Introduction
Vision-Language-Action (VLA) models [ 5 , 17 , 3 , 28 , 41 , 40 ] map a language instruction and the current observation directly to low-level actions, and have become a standard approach to language-conditioned manipulation. The policy is re-queried on each new observation, yet nothing checks whether the current observation satisfies the intended goal. Execution therefore continues under the same instruction even after a step has failed. Consider an object that slips from the gripper during transport. The post-slip state is rare in the demonstrations, so the policy rarely re-grasps and may instead continue its learned trajectory, for example by placing with an empty gripper. On a long-horizon task, that unnoticed failure leaves the remaining steps unfinished, and the episode fails even though earlier progress was correct. One route is to place this decision-making functionality inside the action model. Systems built on GPT-6-Astra [ 27 ] use one large model to generate numerical robot actions, judge the outcome during execution, and emit a correction within the same forward pass [ 12 ] . However, the scale that enables such judgment and correction also slows every inference step. Even steps that a fast policy could execute unchanged must wait on the large model, and the resulting latency falls short of the control rate required for physical deployment. Dual-system architectures instead place the decision model outside the action model. In Helix and related systems, a high-level model passes a language command, a token, or a latent vector to a single low-level policy [ 9 , 28 , 30 , 2 , 6 , 38 , 8 , 29 ] . This interface changes what the low-level policy is conditioned on, but it cannot express a failed attempt, a retry, or a switch to a different executor. Code-as-policy methods provide exactly this control flow, in which an agent writes a program that tests the outcome of each skill and retries it on failure [ 20 , 14 , 31 , 13 , 21 ] . Because these programs call primitives or VLA skills from the first step, they largely discard the long-horizon competence of a full-task VLA. Code is therefore better used to wrap one attempt by that VLA, and to close the loop only after the attempt fails. Building on this principle, we propose RoboDuo, a dual-system framework in which a coding agent uses code as the interface to two frozen VLAs (Fig. 1 ). The agent serves as an orchestrator and writes a task program. The program first assigns the task to the full-task VLA for one attempt, after which is_task_complete evaluates the new observation. If the task fails, the agent plans the unfinished steps from the current observation as atomic instructions. An atomic VLA then executes these instructions to the end of the task, with at most three attempts per step, and the control does not return to the full-task VLA. We employ a separate atomic VLA since each atomic instruction describes a short segment already present in the demonstrations, whereas the full-task VLA is trained only on full-task instructions. We construct LIBERO-Atomic, LIBERO-Code, and LIBERO-Judge from the same demonstrations to train the atomic VLA, the coding agent, and the completion check, respectively. We instantiate RoboDuo on X-VLA and \pi_{0.5} without updating the weights of either full-task VLA. On LIBERO-Long, RoboDuo raises the success rate of X-VLA from 87.4% to 91.6% and that of \pi_{0.5} from 93.6% to 96.2%. On LIBERO-PRO, RoboDuo raises the mean success of \pi_{0.5} from 32.05% to 39.33%, with the largest gain on Object-T ( 25.2\rightarrow 55.8 ). On a real robot, RoboDuo raises success from 36.7% to 53.3% over three fruit-arrangement layouts, without updating the frozen full-task VLA. Our main contributions are summarized as follows: • We propose RoboDuo, a closed-loop dual system that uses code, rather than a token or a latent vector, as its interface. When the full-task VLA fails, an atomic VLA executes the remaining steps. • We construct LIBERO-Atomic, LIBERO-Code, and LIBERO-Judge from the same successful demonstrations to train the atomic VLA, the coding agent, and the completion check, respectively. • We instantiate RoboDuo on X-VLA and \pi_{0.5} and evaluate it on LIBERO, LIBERO-PRO, and a real robot. The gains concentrate on long-horizon tasks that fail because a single subtask fails.

## 3 Method
RoboDuo turns a single VLA rollout into a verified attempt. A coding agent writes a program that gives a frozen full-task VLA one attempt on the original instruction and then tests the resulting observation with a completion check. If the test fails, the program executes the remaining subtasks with an atomic VLA, which is trained on short clips that each contain a single complete skill. The two VLAs produce every action, whereas the coding agent and the completion check only decide which VLA to query and which instruction to give it.
