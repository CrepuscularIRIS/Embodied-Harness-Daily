# VABAR: A Variational Automation Benchmark for Agentic Robotics

## Abstract
For robots to operate reliably in commercial and industrial applications, they must persistently perform specific tasks with known variations in object shape and pose. We call this Variational Automation (VA) to differentiate these settings from fixed automation. Inspired by recent papers on Agentic Robotics, where pretrained LLM and VLM coding agents combine interpretable robot programming with the open-world adaptability of model free policies, we propose a general set of agentic robotics benchmark design criteria that includes accessibility, repeatability, diversity, relevance to agentic robotics and practical applications, physical realizability, resistance to benchmark saturation, and computational efficiency. We instantiate these principles in six manipulation task classes spanning industrial, medical, and infrastructure applications: tool sorting, tool hanging, gear meshing, syringe packing, cable insertion, and cable routing. We introduce the Variational Automation Benchmark for Agentic Robotics (VABAR), an open, easily replicable, simulation-based manipulation benchmark to systematically evaluating agentic robotics systems. Built fully on open-source tools, VABAR features detailed implementations using the Newton physics engine, standardized task variations, difficulty tiers, success metrics, and a library of 33 generalizable skills with human-authored programmatic reference solutions. We provide initial baseline evaluations using an open agentic manipulation harness, Graph-as-Policy (GaP), and Isaac Lab Arena.

## I Introduction
For robots to operate reliably in commercial and industrial applications, they must solve Variational Automation (VA) tasks, where operational objectives and workspace persist with structured variations in objects, layouts, task parameters, and execution conditions across instances. In fixed automation , robots repeatedly execute carefully engineered programs in highly structured environments, often achieving high reliability and throughput but requiring substantial human effort to design, deploy, and retune when conditions change [ 1 ] . In comparison, generalist robotics aims to perform a broad range of open-ended tasks, but current model-free end-to-end approaches struggle to achieve the speed and reliability required for commercial and industrial adoption. VA tasks lie between fixed automation and fully generalist robotics. Recent advances in agentic robotics provide a promising approach to implementing VA by combining the reliability and interpretability of classical robot programming with the adaptability of learned policies. Rather than directly mapping observations to low-level actions through a monolithic model-free policy, agentic robotic systems use multiple LLM agents to reason about task instances, generate and modify executable robot programs, and invoke perception, planning, and control modules named skills. Existing robot manipulation benchmarks (e.g., LIBERO [ 2 ] , ManiSkill [ 3 ] , and SimplerEnv [ 4 ] ) evaluate the robustness and generalization of language-conditioned deep visuomotor policies by offering simulation environments, human-teleoperated training episodes, and success metrics across new scene configurations. Many of these have recently been saturated by systems that achieve very high success rates and they primarily focus on household pick-and-place tasks. We introduce VABAR , a Variational Automation Benchmark for Agentic Robotics . VABAR provides six application-oriented manipulation task classes spanning industrial, medical, and infrastructure settings: tool sorting, tool hanging, gear meshing, syringe packing, cable insertion, and cable routing. Each task is defined with a set of instances with explicit variation axes, difficulty levels, and success conditions. For each task, we provide a physics and photorealistic simulation environment, a set of generalizable skills to facilitate execution, and a human-authored reference solution expressed as a computation graph over the same skill library. The reference solution is executed with the same perception, planning, and execution stack available to coding agents. We evaluate VABAR using GaP, an open agentic manipulation baseline [ 5 ] , and with Isaac Lab Arena to establish baselines and to study how performance scales with task difficulty and structured variation. This paper makes 5 contributions: 1 Variational Automation task formulation. We introduce and formalize Variational Automation , a manipulation class between fixed automation and unconstrained general-purpose manipulation, in which persistent operational objectives must be achieved across a structured distribution of task instances. 2 Design principles for agentic robotics benchmarks. We define practical criteria for evaluating agentic systems, emphasizing accessibility, repeatability, controlled diversity, application relevance, physical realizability, resistance to saturation, and computational efficiency. 3 VABAR task definition We instantiate these principles in six application-oriented manipulation task classes—(1) tool sorting, (2) tool hanging, (3) gear meshing, (4) syringe packing, (5) cable insertion, and (6) cable routing—with standardized task variations, difficulty levels, success metrics, and support for single-arm Franka and bimanual YAM embodiments. 4 VABAR simulation, Agentic Skills and Human-authored solutions For each task, we provide a photorealistic simulation environment, 33 generalizable skills that facilitate solving the tasks, and a human-authored code solution. 5 Initial agentic manipulation baselines. We provide initial baseline evaluations using an open agentic robotic system and characterize performance as task complexity and instance variation increase, establishing reference results and identifying remaining challenges for agentic manipulation.

## III Criteria for Agentic Robotics Benchmarks
III-A Agentic Robotics Benchmark Design Criteria 1. Relevance to agentic robotics. The benchmark should support evaluating agents that construct, test, and revise robot programs from task specifications. It should provide documented robot and tool interfaces for composing perception, planning, and manipulation capabilities, together with execution feedback for program and skill refinement during development. Evaluation should assess reliable task completion across variations without prescribing a particular program representation or agent architecture. 2. Application relevance. Tasks and variations should reflect realistic operating requirements, with benchmark results predictive of real-world success, cycle time, and intervention needs. 3. Accessibility and clarity. Benchmark environments, task specifications, assets, evaluation metrics, and variation parameters should be publicly available and clearly documented so that independent researchers can reproduce and extend the evaluation. 4. Controlled diversity. Each task should specify explicit variation axes and difficulty levels rather than rely solely on unconstrained randomization. 5. Repeatability. Task generation and evaluation should use controlled random seeds and standardized success criteria to support repeatable experiments and meaningful comparisons between methods. 6. Computational efficiency. Evaluation should be computationally efficient enough to support repeated experimentation, sensitivity analysis, and large-scale benchmarking. 7. Durability. The benchmark should support systematic extensions of variation ranges and task complexity to remain informative as robotic systems improve. Extensions should be versioned to preserve comparability with previously reported results. III-B Task Definition We define a Variational Automation (VA) task class as \mathcal{T}=(\mathcal{E},\mathcal{R},\mathcal{A},\mathcal{O},p_{\mathcal{O}},\mathcal{S}), where \mathcal{E} defines environmental coordinate frames, \mathcal{R} denotes the robot and gripper specification, \mathcal{A} denotes the set of admissible initial assets, each with physical properties and collision mesh, and \mathcal{O} denotes the space of admissible object configurations. p_{\mathcal{O}} defines a distribution over admissible object configurations, and \mathcal{S} denotes the measurable success condition. Each task instance configuration \tau_{i}=\left\{(a_{j},\,\mathbf{x}_{j})\right\}_{j=1}^{N_{i}}\in\mathcal{O}, specifies each instantiated a_{j}\in\mathcal{A} and its initial pose \mathbf{x}_{j}\in SE(3) for each of the N_{i} objects and fixtures in the scene. Importantly, \mathcal{O} is not defined by unconstrained scene randomization. Instead, the variation space and its sampling distribution are designed to represent meaningful changes in the operating conditions of an automation task.
