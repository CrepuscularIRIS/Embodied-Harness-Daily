## 1 Introduction
Flipping is a fundamental robotic manipulation skill that requires reorienting a target object in a stable pose on a planar support surface by rotating it 180 ∘ about an axis parallel to the support surface – think of flipping a coin from heads to tails. Although flipping is a common objective in industrial tasks such as parts inspection, mechanical assembly, and tool use, coding a bimanual robot with grippers to flip diverse objects is a significant challenge. Flipping may require diverse strategies depending on object geometry, robot kinematics, and contact constraints [ 2 , 6 , 12 , 11 , 10 ] . For example, flipping a hammer may require a bimanual handover, whereas flipping a wide multimeter may require coordinated pushing and toppling. Such diversity introduces distinct action modes and coordination challenges for visuomotor policies and Vision Language Action models. In this short paper, we present FlipAnything , an Agentic Robotics benchmark and case study. We use RoboSimStudio [ 4 ] and our Graph-as-Policy (GaP) harness [ 3 ] with Claude Fable 5.1 [ 1 ] , to iteratively develop and refine an algorithmic solution through simulation-based self-learning without demonstration data. The resulting graph-based code uses RGB-D observations and robot proprioception to control bimanual YAM arms. We find that structured code provides several distinct multimodal manipulation behaviors, enabling a single policy to select and compose strategies such as bimanual handover, repositioning, pushing, and toppling based on perceived geometry and robot constraints. Iterative simulation-based self-learning enables the agent to identify failure modes, refine its control logic, and progressively improve coverage across diverse task instances. Results across 360 evaluation episodes involving 24 objects show that the graph-based code’s success rate improves from 24.7% to 95.0%. The code learned in simulation can also transfer zero-shot to real-world manipulation of unseen objects, including a clamp, blue tape, and a foldable helix screwdriver.

## 2 Method
Overview We describe the flipping task in English and provide CAD models of 24 objects and the URDF of the YAM arms as inputs to an iterative code-generation and evaluation loop, where the coding agent improves the executable policy [ 7 ] through interaction with a physics simulator [ 5 , 3 ] . We use RoboSimStudio [ 4 ] and Newton for rigid-body physics simulation, with a MuJoCo-based solver [ 8 ] and CoACD [ 9 ] for convex decomposition of object meshes. We use the GaP harness [ 3 ] with Claude Fable 5.1 [ 1 ] as the coding agent to generate execution graphs. The agent has access to the simulator’s execution context, including spatial information and execution results. Agentic Self-Learning . Given the flipping task and benchmark objects, the agent generates an initial graph that attempts flipping through bimanual handover. Then, it evaluates the generated flipping techniques across a set of objects with randomized positions for each object. After each evaluation, the agent analyzes success rates, execution traces, and failure modes, including infeasible grasps, lost contacts, failed handovers, and incorrect orientation estimates. Based on this feedback, the agent revises the code by refining perception, grasp selection, motion primitives, strategy selection, and recovery logic. The updated controller is then re-evaluated across the object set to measure improvements and detect regressions. Unlike gradient-based policy training, the learned artifact is a graph that can be converted into an executable program whose conditional logic and control parameters are progressively refined to cover the 24 object geometries and manipulation strategies.

## 3 Results
Self-Learning Improves FlipAnything Performance . We evaluate the agent-generated graph across 24 objects, with 15 evaluation episodes per object, totaling 360 episodes per iteration. Starting from an initial handover-only controller, the agent achieves a success rate of 24.7% (89/360). After self-learning additional manipulation strategies, including stand-and-topple and push-based flipping, the success rate increases to 80.6% (290/360). Subsequent self-improvement iterations refine grasp stability, geometric reasoning, contact handling, and recovery behaviors, progressively increasing performance to 95.0% (342/360) in the best tuned controller. These results suggest that agentic robotics can improve manipulation performance by identifying failure modes and modifying its executable control logic, rather than training separate policies for different objects. Code Representation Can Generalize Across Manipulation Strategies. Qualitative results show that the agent progressively develops distinct manipulation strategies to accommodate different object geometries and constraints, instead of a single grasp-and-rotate motion. For long-handled objects such as the claw hammer, the graph-based code performs an in-air bimanual handover, achieving 14/15 successes. For compact objects such as lock nuts, where a second grasp is difficult, the graph-based code instead uses table-supported manipulation, first standing the object on its edge and then pushing it beyond the tipping point, achieving 15/15 successes on both lock nuts. Wide objects such as multimeters are flipped through coordinated fingertip pushing without requiring a stable grasp, achieving 15/15 successes. When workspace constraints prevent a feasible handover, the graph-based code first repositions the object before attempting the flip, as demonstrated by tape measures (14/15) and pipe wrenches (13/15). Thin objects such as surgical scissors require guarded-contact grasping and slower rotation to prevent slippage, improving from 0/15 successes in earlier graph-based code versions to 13/15 in the final controller. Beyond selecting these strategies, the final code incorporates closed-loop recovery behaviors, including in-hand pose correction, grip verification, and additional pushing when an object only partially flips over. Future Work. We evaluate the FlipAnything code in real-world experiments on three objects whose geometries were not encountered during simulation-based self-learning: a clamp, blue tape, and a foldable helix screwdriver. Without object-specific tuning, the code succeeds in 2 of 3 trials for the clamp, 3 of 3 trials for the blue tape, and 1 of 3 trials for the foldable helix screwdriver. We will study generalization to unseen objects in future work.
