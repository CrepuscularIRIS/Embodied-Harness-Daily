# FORCA: A Force-Aware Coding Agent for Contact-Rich Robot Manipulation

## Abstract
Coding agents can translate language instructions into robot programs. For contact-rich manipulation, a key challenge is to generate and refine control logic that responds to physical interaction. We present FORCA, a coding agent that takes visual observations and wrist force/torque (F/T) measurements as input to write Python programs for contact probing and force-responsive motion. Between executions, the agent inspects force records alongside visual outcomes to diagnose failures and revise both motion and force-feedback control logic. FORCA requires no demonstrations, task-specific training, or simulation. Across five real-robot tasks, we demonstrate its effectiveness in three forms of contact-rich manipulation: improving manipulation accuracy, adapting to changes in object or surface properties, and regulating contact under surface variation and object motion. Compared with a vision-only variant of the same agent, FORCA improves grasp accuracy and task success and reduces contact loss in wiping and peeling.

## I Introduction
Coding agents based on foundation models turn open-ended instructions into executable robot programs that compose perception, grasping, and motion skills [ 1 , 2 , 3 , 4 ] . They ground their decisions mainly in vision and proprioception, which is often insufficient for contact-rich manipulation: occluded or reflective surfaces yield uncertain geometry, mass and friction are not visible, and maintaining contact requires responding to surface variation and object motion. Force and contact measurements complement vision by providing evidence about contact states and mechanical responses that are difficult to infer from visual observations alone. Learned policies exploit force and tactile signals for reactive control but require demonstrations or robot data [ 5 , 6 , 7 , 8 ] . Foundation-model agents have used force through compliant or force-thresholded primitives [ 9 , 10 ] , inferred physical properties largely from priors [ 11 , 12 , 13 ] , and revised force targets after failed attempts [ 14 ] . Supporting these diverse tasks requires agents to determine when contact information is needed, how it should guide ongoing motion, and how unexpected contact outcomes should inform subsequent attempts. We present Forca , a training-free coding agent that uses wrist force/torque (F/T) sensing in both program execution and program revision (Fig. 1 ). It writes complete Python programs with access to the measured wrench. During a rollout, the program uses measurements from contact probes to guide subsequent actions and uses live force feedback to regulate its motion. Between rollouts, the agent relates the recorded force traces to visual outcomes, diagnoses failures, and revises the program. Forca addresses three types of contact-rich manipulation: (i) precision manipulation , where force cues help refine grasp poses and improve manipulation accuracy; (ii) physical adaptation , where actions must be adjusted to changes in object or surface properties; and (iii) contact regulation , where motion must respond to surface variation and object movement. We evaluate Forca on five real-robot tasks spanning these categories: drawer opening, door-handle operation, cube-to-target knocking, vase wiping, and cucumber peeling. Compared with a vision-only variant of the same agent, Forca increases task success from 40% to 100% for drawer opening and from 10% to 100% for door-handle operation, while reducing contact-loss rates in wiping and peeling from 40.6–55.9% to at most 2.2%. Our contributions are twofold. First, we introduce a coding-agent framework that generates task-specific motion and force-feedback control logic from language instructions. The resulting programs use measured contact to refine grasp poses and regulate motion during execution. Second, we extend program refinement to the force-feedback logic itself, enabling coding agents to revise how their programs respond to contact based on evidence from real-robot execution.

## III Method
Given a language instruction and RGB-D observations, Forca writes a Python code with access to wrist force/torque (F/T) measurements. The program executes on the robot without querying the foundation model. After execution, the agent reviews the recorded interaction and revises the code (Fig. 1 ). We refer to one execution of a program as a rollout . III-A Force-Aware Program Synthesis For each task, the agent generates a Python task program that specifies the action sequence and the force-dependent motion logic. To construct this program, the agent has access to an initial skill codebase for perception, grasping, motion planning, and pick-and-place, assembled from open-source components under human supervision. These predefined modules provide object pose estimates, grasp candidates, and collision-free trajectories computed with PyRoKi [ 30 ] . Figure 2 illustrates these modules as the robot acquires a whiteboard eraser for the instruction “Wipe the vase.” The agent writes the force-dependent logic for each task using wrist wrench measurements exposed by the robot interface. For example, this logic can specify when an approach should stop or how motion should respond to a force error. To implement these behaviors, the agent can modify existing routines or add measurement and control code as needed. III-B Contact-Responsive Execution During a rollout, the generated program uses F/T measurements to guide subsequent actions and adjust ongoing motion. The conditions and feedback rules governing these responses are encoded in the program and executed without querying the foundation model. Contact measurements can inform actions by refining the geometric estimates on which they depend. For example, the program can probe a surface before grasping, specifying both the probing motion and the force condition used to detect contact. The robot pose at contact, together with the tool geometry, provides an updated estimate of surface height or grasp position. Subsequent motions use this estimate within the same rollout. For actions that require sustained contact, the program uses live force feedback to regulate motion. A host-side 100 Hz loop reads the wrench and robot state over RTDE and updates Cartesian velocity commands according to the generated control logic. This logic can adjust motion based on the difference between measured and target force, or pause forward motion when contact is insufficient and resume it once contact is restored. III-C Execution-Grounded Program Revision After each rollout, the agent inspects visual observations alongside the recorded force and robot-state traces. The agent can write analysis code to examine relevant time windows and relate force changes to robot motion and visible outcomes. The agent uses these records to identify possible causes of failure and revise the relevant code. Changes can affect motion parameters or contact conditions, and can also modify the control logic or action sequence. Figure 3 illustrates one such revision in cucumber peeling. Skin remains exactly where the recorded force shows that the blade lost contact, so the agent makes the blade wait for contact before moving on. Before execution, checks screen the revised code and planned motions for errors, reachability, and workspace violations. Revision stops when the agent declares the program converged or when either the rollout or wall-clock budget is exhausted. Development budgets and evaluation protocols are described in Sec. IV-A .

## IV Experiments
We consider three ways in which force/torque feedback can benefit manipulation: (i) improving manipulation accuracy , by complementing visual estimates with contact-based geometric information to refine grasp poses and guide subsequent actions; (ii) adapting to physical changes , by providing evidence about how object properties affect action outcomes to adjust manipulation accordingly; and (iii) regulating contact , by using live force measurements to adjust ongoing motion and maintain contact as surfaces vary or objects move. Our experiments evaluate how effectively Forca uses contact information across these three settings, combining comparisons against a vision-only agent with case studies of the generated programs.
