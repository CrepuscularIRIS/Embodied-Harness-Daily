# Robocasa-Mem: Benchmarking Environment and Process Memory in Long-Horizon Mobile Manipulation

## Abstract
In the real world, mobile manipulation robots must perform complex object interactions and make multi-step decisions, often relying on task-relevant information that is no longer observable. However, existing benchmarks provide limited evaluation of such memory-dependent decision-making in mobile manipulation. To address this gap, we introduce RoboCasa-Mem, a new benchmark comprising nine mobile manipulation tasks that require agents to use interaction history at key decision points. Specifically, the tasks are grouped into two categories of memory: One is environment memory, which captures spatial locations, object attributes, and object relationships. The other is process memory, which captures single-task progress and multi-task scheduling. Particularly, we introduce Behavior-Conditioned Evaluation. For tasks with multiple valid execution paths, instead of fixing a single target or trajectory, the evaluator derives later task constraints from the robot's earlier actions. This allows us to evaluate whether later behavior is consistent with the robot's own interaction history while reducing shortcuts based on fixed target assignments. We provide 1,800 successful demonstrations for policy training. We also develop a baseline on our benchmark, namely Hierarchical Memory-Augmented Policy(HMAP). Its high-level planner uses structured entity and process memories to generate subtasks. Its low-level VLA controller uses subgoal-conditioned queries to incorporate VGGT-Omega geometry into action generation. Together, RoboCasa-Mem and HMAP baseline support systematic evaluation of memory-dependent behavior and the development of memory-aware mobile manipulation policies.

## 1 Introduction
Mobile manipulation requires robots to navigate between locations and interact with objects ( Szot et al., 2021 ; Nasiriany et al., 2024 ) . While tabletop manipulation often concentrates task-relevant information within a fixed workspace, mobile manipulation extends interactions across different work areas. As the robot moves and interacts with the environment, previously observed information may become inaccessible yet remain essential for subsequent decisions. For example, when cooking, a robot may need to remember whether it has already added salt to the pot after the salt has dissolved and is no longer visually distinguishable. Such situations motivate maintaining historical information about both the environment and task execution, beyond what is available in the current observation ( Torne et al., 2026 ) . Memory dependence is not equivalent to long-horizon manipulation. A task may involve multiple sequential steps without requiring historical information, provided that the current observation is sufficient for decision-making. Conversely, even a short task may require memory when critical information is no longer observable. From a partially observable decision-making perspective, historical information is needed when different interaction histories yield indistinguishable current observations but require different subsequent decisions ( Kaelbling et al., 1998 ) . We therefore evaluate memory based on the necessity of historical information for correct decision-making, rather than task length or execution complexity alone. Existing mobile-manipulation benchmarks, such as RoboCasa ( Nasiriany et al., 2024 ) , RoboCasa365 ( Nasiriany et al., 2026 ) , MS-HAB ( Shukla et al., 2025 ) , BEHAVIOR-1K ( Li et al., 2024 ) , and the suite of works based on Habitat ( Puig et al., 2024 ; Szot et al., 2021 ; Savva et al., 2019 ) , primarily evaluate task execution, long-horizon control, generalization, and policy learning, without explicitly isolating decisions that require historical information. In parallel, robotic memory benchmarks such as RMBench ( Chen et al., 2026 ) , RoboMME ( Dai et al., 2026 ) , RoboMemArena ( Lei et al., 2026 ) , and RoboTwin-MeM ( Yang et al., 2026 ) study history-dependent manipulation, predominantly in tabletop or fixed-base settings. Mobile manipulation brings these memory demands into settings where robots move between work areas, lose visual access to previously observed entities, and must resume unfinished activities. Two requirements are particularly relevant: retaining object states established through earlier interactions but no longer visually distinguishable , and tracking progress and pending actions across interleaved activities in different regions . Although neither requirement is unique to mobile manipulation, their joint evaluation under changing viewpoints and cross-region execution remains limited. To systematically characterize these requirements, we organize memory into two complementary dimensions: Environment Memory and Process Memory . Environment Memory captures information about the physical environment that cannot be reliably recovered from the current observation, encompassing Spatial Memory , Attribute Memory , and Relational Memory . Process Memory tracks task execution states and information needed to determine subsequent actions, encompassing Single-Task Progress and Multi-Task Scheduling . This taxonomy explicitly accounts for visually unobservable object attribute changes and the scheduling of interleaved tasks, providing a systematic characterization of memory requirements in mobile manipulation. Based on this taxonomy, we introduce RoboCasa-Mem , a benchmark for memory in mobile manipulation. RoboCasa-Mem contains nine mobile-manipulation tasks covering the five memory categories above. Each task is designed to introduce observation-insufficient decision points , where the current observation alone cannot determine the appropriate action, requiring the robot to retrieve and utilize information from its interaction history. This design explicitly evaluates memory dependence rather than relying on task horizon as its proxy. For tasks with multiple valid execution paths, we introduce Behavior-Conditioned Evaluation , which derives later constraints from the policy’s own earlier interactions rather than fixing a target in advance. This allows history-consistent behavior to be evaluated without prescribing a single execution trajectory. To provide a baseline, we develop a Hierarchical Memory-Augmented Policy (HMAP) that combines structured memory for planning with geometry-augmented control. A high-level planner maintains Entity Memory and Process Memory to track environment states, execution progress, and pending actions, and generates executable subgoals. ## 3 The RoboCasa-Mem Benchmark
RoboCasa-Mem contains nine household mobile-manipulation tasks covering five memory types under two groups: Environment Memory and Process Memory . Figure 1 gives an overview of the benchmark. 3.1 Memory Demand and Task Design Memory-dependent task design. We design tasks such that information required for a later decision is observed earlier but cannot be reliably recovered from the current observation. For example, after sugar dissolves in water, the current image does not reveal whether sugar was previously added to a cup. The policy must therefore retain information from earlier interactions rather than relying only on the current observation. This distinguishes memory dependence from task horizon: a task may contain many steps without requiring memory if each decision can still be made from the current observation. We formalize this design principle using observation aliasing in partially observable environments ( Kaelbling et al., 1998 ) . Let x denote the task instruction, o_{t} the current observation, and h_{t}=(o_{1},a_{1},\ldots,a_{t-1},o_{t}) the interaction history. For a semantic query q , let \mathcal{G}^{\star}_{q}(h_{t},x) denote the set of acceptable responses. Historical information is required when two feasible histories satisfy o_{t}(h_{t})=o_{t}(h^{\prime}_{t}),\qquad\mathcal{G}^{\star}_{q}(h_{t},x)\cap\mathcal{G}^{\star}_{q}(h^{\prime}_{t},x)=\varnothing. (1) That is, similar current observations may require different decisions because of different interaction histories. We use this condition as an idealized task-design criterion rather than requiring observations to be exactly identical at the pixel level. 3.2 Task Classification The nine tasks are grouped according to the historical information required for later decisions.
