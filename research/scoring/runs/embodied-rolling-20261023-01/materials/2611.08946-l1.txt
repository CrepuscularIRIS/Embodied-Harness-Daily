# Flex-RSI: Benchmarking Recursive Self-Improvement of Frontier Agents

## Abstract
Frontier language models are increasingly deployed as agents, and how well an agent performs depends not only on its model but also on its harness: the prompts, tools, memory, and control loop through which the model acts. When an agent is applied to a new problem, a natural question is whether it can use the feedback of the task to improve the way it works, and not merely its answer. Most existing benchmarks keep the agent's harness fixed and score the solution it produces, or target large-scale model training. We introduce Flex-RSI, a benchmark for the recursive self-improvement of agents on vision and robotics tasks under a fixed budget. In each round, an executor improves the task solution, which is kept only if it scores higher on held-out validation data, and an improver then revises the harness, including the executor and itself. Every run starts from the same general-purpose harness, and the final solution is scored on hidden test data. Evaluating closed-source and open-weight models on tasks spanning perception, reasoning, robot action, 3D reconstruction, visual creation, and infrastructure, we find that self-improvement helps most when the agent builds its own solution, that feedback recording only success or failure holds back open-weight models, and that open-weight models fall furthest behind where outputs must pass strict checks of physical stability or exact correctness. Paired runs further show that editing the harness itself contributes to the gains.

## 1 Introduction
Frontier large language models now routinely act as agents that write code, conduct experiments, and read the results over multiple steps ( Anthropic, 2026a ; OpenAI, 2026b ; Google DeepMind, 2026 ; Qwen Team, 2026b ; DeepSeek-AI, 2026 ; GLM-5 Team, 2026 ) . An agent’s performance depends not only on the underlying model but also on its harness : the prompts, tools, memory, and control loop through which the model acts. This raises a practical question for anyone who deploys an agent on a new problem: given only the task, can the agent use the task’s feedback to improve the way it works under a fixed budget, and not merely its answer? Most existing benchmarks run each model inside a fixed harness, often the vendor’s own, and score only the solution or artifact it produces, mostly on machine-learning research tasks with a continuous metric ( Chan et al., 2025 ; Wijk et al., 2024 ) ; those that also let the agent revise its harness ( RSI-Exam Team, 2026 ) or that center on upstream model training at scale ( OpenRSI Foundation, 2026 ) remain within machine-learning research. We introduce Flex-RSI to measure how well a frontier agent improves both its solution and its own harness on general vision and robotics tasks, a setting in which agents are increasingly deployed, each attempt consumes real compute, and the goal is a better solution within hours to days. In Flex-RSI, the harness consists of two components that alternate over rounds ( Figure 1 a). The executor improves the task solution: it modifies the solution, runs experiments, and evaluates them on the labeled development data, and its candidate is kept only if it also scores higher on held-out validation data. The improver then reviews the round and modifies the harness itself, including the executor’s prompts, tools, and workflow as well as its own prompts, settings, and lessons. Every run starts from the same general-purpose harness and, on each task, the same starter solution. The tasks differ in what the agent must produce (a single answer or a solution it builds), how the evaluator scores it (on a scale or only as success or failure), and how strictly the output is checked. From experiments on 24 tasks spanning perception, reasoning, robot action, 3D reconstruction, visual creation, and infrastructure ( Figure 1 b), with 18 closed-source and open-weight models, we find: 1. Tasks in which the agent builds the solution leave more room for self-improvement: tasks whose solution is a single answer to each question leave little room to improve, while tasks in which the agent builds its own solution leave the most, and there models pull apart ( Figure 1 c). 2. The granularity of feedback matters: feedback that scores each episode on a scale helps all models, whereas feedback that records only success or failure leaves open-weight models barely improving on the solutions they build. 3. Strict checks of physical stability and exact correctness pose the greatest challenge: outputs that look plausible often fail checks of physical stability or exact correctness, and open-weight models fall furthest behind on them. Paired runs further show that letting the improver edit the harness raises the test score in six of seven pairs of otherwise identical runs ( Section 5.4 ).

## 3 Flex-RSI
Flex-RSI evaluates whether an agent, given a task and a fixed budget, can improve not only its solution to the task but also the harness through which it operates. We first define the task setting ( Section 3.1 ), then the self-improving harness ( Section 3.2 ), and finally how runs are evaluated ( Section 3.3 ). 3.1 Problem setup Each task provides the agent with a starter solution, compute resources, a budget, and data partitioned into three disjoint splits. The development split , including its labels, is available to the agent for experimentation and evaluation. The validation split is withheld from the agent and determines which candidate solutions are retained. The test split is likewise withheld and is used only once, after the run terminates, to evaluate the final solution. The objective of the agent is to maximize the test score of its final solution within the budget. On a given task, every run starts from the same starter solution and is subject to the same budget, which limits wall-clock time, GPU hours, model usage, the number of validation evaluations, and the number of rounds. Through its prompts, tools, control loop, and memory, it determines the context presented to the model and the actions available to it. Since the harness consists of code and text, the agent can modify it in the same manner as any other program, while the model weights remain fixed. In Flex-RSI, the harness H=(E,I) comprises two components that query the same model. The executor E operates on the task solution: it modifies the solution, conducts experiments, and evaluates the results on the development split. The improver I operates on the harness: it analyses the executor’s trajectories and results, diagnoses failures, and revises the prompts, tools, and workflow of the executor as well as its own instructions and accumulated lessons.
