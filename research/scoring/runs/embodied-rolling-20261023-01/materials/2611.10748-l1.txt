# REINS: A Self-Evolving Agent Harness for Real-Time Trajectory Planning

## Abstract
Agent harnesses -- runtime scaffolds that wrap an LLM's reasoning loop with tool dispatch, verification, and persistent memory -- have become the standard substrate for deploying LLMs as autonomous agents, as demonstrated by Claude Code and Codex in software engineering. In trajectory planning, however, this paradigm has not taken hold: existing LLM-based trajectory planning methods either keep the LLM in the decision loop, exceeding the millisecond-level control budget, or offload it to offline rules or training-time supervision -- leaving the runtime planner non-evolving. Intermediate hybrids still lack the verification-and-consolidation loop that makes harnesses reliable. We ask: what runtime harness would let an LLM planner meet real-time constraints while self-evolving into a deployable one? We propose REINS, a harness built on three LLM-planner couplings: LLM outputs are (i) grounded to a learned variable-level dynamics model, (ii) verified via calibrated predicates and forward rollout, and (iii) consolidated into an indexed rule memory that serves future scenes in O(log n) without re-invoking the LLM. The harness closes a self-evolution loop: familiar scenes resolve by memory lookup; novel scenes invoke the LLM, whose verified outputs enrich the memory. Without modifying LLM weights, REINS attains 98%+ compliance, nearly 50% collision reduction, and 1.9-4.6 ms latency on simulated and real-world benchmarks at the tactical decision layer, with LLM invocation rate monotonically declining as memory matures. ## 1 Introduction
Trajectory planning is the safety-critical core of autonomous driving: each decision must respect traffic rules, anticipate other agents, and complete within a millisecond-level control budget (e.g., 50 ms at 20 Hz) ( Zhang et al., 2021a ; Falcone et al., 2007 ; Lenz et al., 2016 ; Li et al., 2024b ; Montgomery, 1983 ) . Recent work shows that large language models (LLMs) bring rich semantic priors over traffic norms, agent intent, and safety reasoning that classical planners lack ( Manas et al., 2025 ; Fu et al., 2024 ; Mao et al., 2024 ; Sha et al., 2023 ; Cai et al., 2024 ; Li et al., 2024a ) , yet integrating their reasoning into the runtime loop is bottlenecked: each LLM query takes seconds—orders of magnitude over the control budget—and naive integration leaves the planner either too slow to act or unable to adapt as deployment proceeds. This is precisely the kind of deployment problem—running a stochastic LLM inside a low-latency, safety-sensitive loop—that the agent harness paradigm has recently addressed in software engineering. An agent harness wraps the LLM with a thin runtime layer of tool dispatch, intermediate-result verification, persistent memory, and safety enforcement—as exemplified by systems like Claude Code, Codex, and Cursor-Agent. On Terminal-Bench ( Merrill et al., 2026 ) , harness design has emerged as a primary driver of ranking, with automatic harness optimization surpassing hand-engineered baselines ( Lee et al., 2026 ) . Trajectory planning, however, is a sharp test of the paradigm: its millisecond-level control budget is much tighter than the seconds-to-minutes scale at which coding harnesses operate, and the safety stakes are higher. In this regime, the harness’s generic functions specialize into three couplings between LLM and planner, illustrated in Figure 1 : when an LLM suggests “keep a safe distance” in a car-following scene, the runtime must (i) ground the suggestion to physical state variables (TTC, THW, DHW), (ii) verify the resulting maneuver via forward rollout over a multi-step horizon, and (iii) consolidate the verified maneuver into an indexed rule memory. Existing LLM-based trajectory planning methods span two extremes plus intermediate hybrids, none of which constitutes a harness in the above sense: runtime invocation methods keep the LLM in the decision loop but exceed the millisecond-level budget by orders of magnitude ( Fu et al., 2024 ; Mao et al., 2024 ; Sha et al., 2023 ) ; offline extraction methods discard the LLM at runtime and freeze the planner against scenarios the offline corpus did not anticipate ( Li et al., 2024a ; Tang et al., 2025 ) ; and hybrid designs partially orchestrate the LLM at runtime but stop short of a full harness, lacking explicit verification of LLM commitments and consolidation of verified ones into reusable structure ( Cui et al., 2026 ; Zhang et al., 2025 ) . Across all three, the LLM’s reasoning is either too slow to act on or too detached from the loop to evolve with deployment. This raises our central question: what runtime harness would let an LLM planner satisfy real-time constraints while self-evolving into a deployable one? Each of the three couplings is non-trivial under real-time control: grounding requires bridging natural-language commitments to the planner’s threshold semantics ( Wang et al., 2025 ; Zhai et al., 2025 ) ; verification must catch stochastic, occasionally unsafe LLM outputs before they reach control ( Manas et al., 2025 ; Zeng et al., 2025 ) ; and consolidation must escape per-call LLM latency ( Fu et al., 2024 ; Mao et al., 2024 ) via a memory pattern emerging in agentic AI ( Wang et al., 2023 ; Zhao et al., 2024 ; Ma et al., 2024 ) but not yet transferred to real-time planning. The three are also jointly necessary: without grounding, verification has nothing to check; without verification, consolidation stores unverified content; without consolidation, every scene re-pays the LLM latency cost. When all three are addressed, a self-evolution loop emerges: familiar scenes resolve from the consolidated memory in \mathcal{O}(\log n) time, novel scenes invoke the LLM, whose verified outputs enrich the memory, and reliance on the LLM decreases monotonically as memory matures, with no LLM weight update. We propose REINS , a concrete realization of this harness pattern, instantiated for trajectory planning in driving, that addresses each coupling as follows. Grounding. We learn a world dynamics model over a factored variable space, fusing LLM-derived semantic priors with data-driven dependency discovery. Group-weighted ridge regression selects each variable’s parents, and a per-variable Transformer predicts its evolution under the discovered graph. Every LLM output can then be projected onto this variable space and rolled out under the learned dynamics. Verification. REINS realizes the harness as a two-phase system (Figure 2 ). Offline Preparation (Section 4.1 ) prepares the world dynamics \hat{\mathcal{G}},\hat{\mathcal{F}} for grounding and an initial rule memory \mathcal{R}_{0} for offline consolidation . Online Runtime (Section 4.2 ) executes a per-scene loop: rule-guided planning performs retrieval, scoring, and verification over \mathcal{R} , and online rule acquisition handles memory misses by querying \mathcal{M} and writing verified rules back to \mathcal{R} , closing the self-evolution loop . 4.1 Offline Preparation 4.1.1 World Dynamics Learning This module realizes grounding : we jointly learn dependency graph \hat{\mathcal{G}} and dynamics functions \hat{\mathcal{F}} by combining LLM semantic priors with data-driven structure discovery.
