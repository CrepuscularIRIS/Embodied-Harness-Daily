# Fewer Tokens, Better Action: GPT-6 Astra Robot Agents with 14% Higher Success Rate but 65% Fewer Tokens

## Abstract
Vision-language model (VLM) agents can control robots through visual feedback and action primitives, but repeated LLM calls and redundant observations incur substantial token overhead. We introduce PyRUA-Lean, an interactive code-execution framework in which the agent composes robot primitives, including vision-language-action (VLA) policies, into Python cells that check and retry locally and return only the images and state they request. Across 700 simulated task instances from LIBERO-PRO, RoboTwin 2.0, and RoboCasa365, it raises success from 63.1% to 71.7% over tool calling with the same GPT-6 Astra planner and primitives, using 49% fewer LLM calls and 65% fewer input tokens on jointly solved instances. On RoboDojo, without any VLA policy or privileged information, it reaches 51.6% average success rate (Score 58.2), 19.4 points above the top entry of the public leaderboard. Based on the PyRUA-Lean framework, we train PyRUA-Lean Coder v0.1-4B, an open 4B model, with GRPO on 45 LIBERO-PRO instances; it improves from 18.8% to 44.1% on unseen task instances, surpassing the Qwen3.5-27B base model.

## 1 Introduction
Vision-language models (VLMs) can perform robot manipulation by interpreting visual observations and robot state, then invoking motion, perception, and grasping primitives, including vision-language-action (VLA) policies [ 1 , 13 , 48 , 38 ] . Their efficiency depends partly on how these primitives are exposed to the planner. In a tool-calling interface, an operation that depends on a previous tool’s result generally requires another LLM call. Intermediate results also accumulate in the conversation and are processed again in every later LLM call; in systems such as RPent [ 48 ] , motion primitives automatically return multiple camera images at the end of each step of execution. Tasks requiring repeated localization, motion, and recovery can therefore incur substantial inference overhead, even when individual primitives are reliable. Executable code can reduce this overhead. A program can compose primitives, inspect their outputs, and execute conditional branches or retries before returning control to the LLM. Code-based robot control is well established: Code as Policies and ProgPrompt generate robot programs from language instructions [ 17 , 36 ] , while more recent systems incorporate execution feedback or refine programs across trials [ 10 , 20 ] . Outside robotics, code-based agent interfaces have shown benefits in task completion and context efficiency [ 41 , 2 , 39 ] . These findings motivate our central question: how can an LLM agent compose robot primitives to reliably complete tasks while reducing token consumption through selective observation and context management? We introduce PyRUA-Lean (Python for Lean Robot-Use Agents), an interactive code-execution interface for feedback-driven primitive composition and selective observation. The agent generates Python programs that compose robot primitives, check intermediate outcomes, and condition subsequent actions on execution feedback. Intermediate results remain available in a persistent program state, while only explicitly printed outputs and requested camera images are returned to the LLM. This allows the agent to handle intermediate execution steps without additional LLM calls and to control which observations enter its context. This report studies the interface from three sides (Figure 1 ). First , we compare it with tool calling under controlled conditions. PyRUA-Lean builds on RPent’s robot stacks and primitive implementations [ 48 ] , and we compare it with RPent’s tool-calling agent under the same GPT-6 Astra planner, frozen VLA policies, evaluation task instances, and LLM-call budgets, on 700 simulated task instances from LIBERO-PRO, RoboTwin 2.0, and RoboCasa365. Both agents operate without cross-episode memory, and the comparison evaluates the interfaces as a whole, including their support for control flow, persistent program state, and observation delivery. Second , we ask how far the interface carries a frozen LLM on a benchmark built for pretrained robot policies. On RoboDojo [ 8 ] , we give the same planner a small library of geometric primitives that we wrote ourselves, and follow the benchmark’s evaluation protocol. The agent uses no VLA policy, no demonstrations, no fine-tuning, and no privileged information: everything it observes is the RGB observation that the benchmark sends to every policy. Third , we ask whether a small open model can learn the interface. Based on the PyRUA-Lean framework, we train Qwen3.5-4B [ 30 ] to write the cells itself, using GRPO [ 35 ] with task success as the only reward, and call the resulting planner PyRUA-Lean Coder v0.1-4B. Our contributions can be summarized as: • PyRUA-Lean, a token-efficient code interface for robot agents. The agent composes robot primitives, VLA policies included, into Python cells that check outcomes, keep state, and return only the observations they request. With the same planner and primitives as tool calling, it raises success from 63.1% to 71.7% and, on jointly solved instances, uses 49% fewer LLM calls and 65% fewer input tokens (Section 3 ). • State-of-the-art results on RoboDojo. With GPT-6 Astra as the planner, no learned policy acting on the robot, and no privileged information, PyRUA-Lean reaches 51.6% average success rate (Score 58.2), 19.4 points above the top entry of the public leaderboard and 2.3 times the same LLM controlling the end-effector directly, and is the highest on all five capability dimensions (Section 4 ). • PyRUA-Lean Coder v0.1-4B, an open planner trained to use the interface. Using the PyRUA-Lean framework, we train Qwen3.5-4B with GRPO on only 45 LIBERO-PRO instances. On tasks and benchmarks it never saw, its success rate rises from 18.8% to 44.1%, above the Qwen3.5-27B base model; on RoboTwin 2.0 alone, from 14.0% to 52.4%. We will release the weights (Section 5 ).
