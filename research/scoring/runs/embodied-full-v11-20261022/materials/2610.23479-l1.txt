# HexaShell: A Thin Harness for Exploring the Limits of VLM Agents as Robot Coding Agents

## Abstract
Agents built on vision language models (VLMs) now compete with learned policies on robot manipulation leaderboards. We ask how far a coding agent can go when it controls a robot instead of a computer, and where it stops. Our system, HexaShell, gives the agent a thin harness: one command line that turns its commands into robot motion and makes no decisions of its own. On the robot, the agent keeps doing what it does best: it reads output, writes code and runs tests. Two agents of the same model share the work. An acting agent runs each episode. After a failure, an optimizer agent reads the full record of the episode, with every command, image and message, finds the cause, and writes or fixes small programs called tools, each with its own tests. What the agents learn stays as code, and no demonstrations or training are needed. At run time, the tools use only what a real robot also has: RGB images, camera calibration and the state of the arms. They find objects by triangulation between camera views. Because these inputs are the same in simulation and on hardware, the tools move to a real robot with a different arm after only a small change for the arm. We build the tools on ten layouts of one seed per task with Codex and GPT-6-Astra and freeze them; the eight Open tasks share one set of tools. In RoboDojo's official evaluation on a hidden seed, 50 episodes for each of the 42 tasks, HexaShell reaches 46.9% success and a progress score of 53.2, the state of the art on the official RoboDojo leaderboard. The limit is contact, not reasoning: memory tasks reach 81.0%, but precision tasks only 32.0%. We open source the tools evolved so far at https://github.com/HexaFuture/HexaShell.

## 1 Introduction
Figure 2 : RoboDojo leaderboard. Altitude is the progress score on the leaderboard’s metric. HexaShell reaches the state of the art in RoboDojo’s official evaluation. Robot manipulation leaderboards have been led by learned policies. Vision language action models and world action models learn from large sets of demonstrations and output the robot’s actions directly [ 35 , 4 , 7 ] . Agents built on vision language models have now started to compete. On RoboDojo [ 14 ] , the model we use reaches 22.5% without tools of its own, choosing gripper targets through a fixed harness written by the benchmark’s authors [ 69 ] . Figure 3 : RoboDojo comparison on the leaderboard’s metrics: success rate (a) and progress score (b). Overall is the leaderboard’s score, the mean of its five task types (Generalization: mean of its standard and cluttered variants). HexaShell: RoboDojo’s official evaluation on a hidden seed, 50 episodes per task, with RGB images only and frozen tools ( Section 4.1 ). GPT-6-Astra is the same model without tools [ 69 ] . Systems are ordered and shaded by Overall success rate. Coding agents suggest another route. In a software repository, a coding agent reads the code, runs it, reads the error and fixes the code, and the fix stays. Recent work has begun to let coding agents write and revise robot tools and programs [ 26 , 25 , 40 , 34 ] . We ask how far a coding agent can go when it works on a robot in the same way, and where it stops. Our system, HexaShell, keeps the harness thin. The agent gets one command, robo, three RGB images with their calibration, and a manual of one page. The harness turns commands into joint motion and does nothing else. What the agent learns is kept as tools, small programs that add commands to robo and may use only what the robot observes. An acting agent tries a layout with the current tools. After a failure, an optimizer agent of the same model reads the episode as it would read a failing test, writes or fixes a tool with its unit tests, and the layout is tried again ( Fig. 4 ). Both agents are Codex with GPT-6-Astra. The hard part is turning pixels into positions. In a repository, everything the agent works on is text it can read exactly. On a robot, the agent sees objects as pixels, but every command needs a position in the world, to about a centimetre for a grasp. Vision language models are known to judge such distances poorly [ 9 , 16 ] . The standard observation has no depth. A monocular depth network can estimate depth from one image, but on RoboDojo scenes Depth Anything V2 [ 65 ] is off by a median of 41 mm at the head camera and about 100 mm at the wrists, even after we fix its scale with the table. Our tools use triangulation instead. The cameras are calibrated, and the robot knows where its wrists are. A point that two cameras see lies where their rays meet, and a point on a measured plane, such as the table, lies where its ray meets that plane [ 27 ] . When one view is not enough, the robot moves a wrist camera to get another. This is active perception [ 3 ] , and on a benchmark it has a price: the motion uses action steps, and every task has a step limit. We build the tools on ten layouts of each task and freeze them. RoboDojo then evaluated the system in its official evaluation, on a hidden seed with 50 episodes per task. On all 42 tasks, HexaShell reaches 46.9% success and a progress score of 53.2 on the leaderboard’s metric, the state of the art on the official RoboDojo leaderboard ( Figs. 2 and 3 ). It does best where the right action follows from measured geometry, and it stops at contact: tight insertion stays low. Over 420 retest episodes, success follows the contact a task needs, not what the agent must read or remember, and how an episode fails separates a gap in perception from a gap in execution ( Section 5 ). The paper makes three contributions. • A thin harness that leaves every decision to the agent. The harness gives an unchanged coding agent one command line to the robot and only turns commands into joint motion, so on the robot the agent still reads output, writes code and runs tests. With it, the same model rises from 22.5% through the benchmark authors’ fixed harness to 46.9% in RoboDojo’s official evaluation, a new state of the art ( Section 4.2 ). • An acting agent and an optimizer agent that turn failures into tested tools. After a failure, the optimizer reads the full record of the episode, with every command, camera frame and message, finds the cause and edits one tool with its unit tests, and the same layout runs again. A round takes a median of 6.3 minutes, and no robot data, training or change to the model is needed ( Section 3 ). • Inputs limited to what any robot has, so the tools generalize. At run time, the tools see only RGB images, the camera calibration and the state of the arms, and measure positions by geometry. Tools built on ten layouts of one seed reach the state of the art on a hidden seed. With 13 to 18 extra objects they keep 82% of their success, more than any learned policy, and triangulation scores 8.7 points higher than a depth network on the same layouts ( Table 1 ). A real robot has the same inputs: on two PiPER X arms, a different model from the simulated ARX X5, the perception and execution tools run after a small change for the arm ( Section 4.7 ). Seven case studies show the loop at work. Each follows a failed attempt through the optimizer’s diagnosis and fix to the next attempt on the same layout ( Section 6 ).
