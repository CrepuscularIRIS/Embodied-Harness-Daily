### 2503.23875 v2 — GenSwarm: multi-robot code-policy generation and deployment via LMs
- **OPERATION**: Extract a constraint pool from the instruction, have LLM agents declare a skill library and dependency graph, write skill bodies bottom-up, LLM-review against constraints plus static checks, run in simulation, let a VLM critique the rollout video, revise, then auto-deploy (Ansible/Docker) to robots.
- **INFO ACCESS**: Frozen LLMs/VLMs (o1-mini, GPT-4o; no fine-tuning). Code sees only local sensing/motion APIs (1 m radius, speed clamp); perception emulated from an indoor positioning system. VLM sees sim video clips; human may add text feedback.
- **CLUSTER**: (e) (multi-robot setting overlaps c).
- **WORKS**: 81% mean SR over 10 tasks × 100 trials, o1-mini (Fig. 6a); 74% vs CaP 40%, MetaGPT 37%, LLM2Swarm 40%, 6 tasks, GPT-4o (Fig. 6b).
- **FAILS**: Hand-tuned Boids / Hungarian+VR-ORCA controllers score higher on average (Supp. Fig. 2). Strongly prompt-sensitive (Supp. Fig. 4–5). Success is thresholded metrics on author-defined tasks. Perception emulated; no onboard sensing (Discussion).
- **COUNTER**: The VLM video-feedback loop adds little: 74% with it vs 71% without (Fig. 6b).

### 2504.09532 v3 — Humanoid-COA: embodied chain-of-action reasoning for loco-manipulation
- **OPERATION**: Caption the egocentric RGB frame to text with a VLM. Have an LLM reason in fixed stages (object affordance, CLIP-weighted region priors for occluded targets, joint-feasibility check), then emit a sequence over a fixed humanoid action library (FIND/MOVE/GRASP/LIFT…). Re-plan after each action.
- **INFO ACCESS**: Frozen GPT-4V (scene text) and GPT-4 (planner). The planner never sees pixels. Execution uses IK end-effector control, navigation commands and a trained load-stable locomotion policy.
- **CLUSTER**: fits K109 good (K104 vocabulary underneath); the paper's own contribution is the staged reasoning prompt.
- **WORKS**: Long-horizon loco-manipulation success 63.3 vs 23.3–26.6 for baselines; occlusion-aware 66.6 vs ≤46.6 (Table IV). Ablation: no reasoning stages 45% success → all three 75% (Table VI).
- **FAILS**: Real robot only, about 30 trials per task (inferred from 3.33% steps). Ablation has no task breakdown or trial count. Baselines are re-implemented. "Executable" is library-syntax validity. REARRANGE primitive only 73.3% success (Table V).
- **COUNTER**: none.

### 2504.14588 v1 — Phoenix: motion-based self-reflection for fine-grained action correction
- **OPERATION**: A fine-tuned MLLM predicts a coarse motion instruction (37 types) at 5 Hz. A second fine-tuned MLLM flags failure and rewrites the instruction via CoT. A motion-codebook-conditioned diffusion policy executes at 20 Hz. Corrected rollouts are folded back into the predictor (lifelong learning).
- **INFO ACCESS**: All parts trained (LLaVA-1.5 ×2, diffusion policy). 160k expert motion pairs plus about 17k correction samples (3,644 online human interventions, 7,365 offline annotations, 6,378 expert) (§4.1).
- **CLUSTER**: (b).
- **WORKS**: 9 RoboMimic tasks, 50 trials each. Mean 57.8% vs motion-conditioned 46.9% and unified-mixture-with-reflection 51.3% (Table 2). Coffee_D0 94 vs 68.
- **FAILS**: Needs human-intervention correction data. Table 1 baseline numbers are not in the text. Human-intervention upper bound uses 10 trials. Real world is one drawer task with 20 corrections (§4.5). Low absolute success on D1/assembly (ThreePieceAssembly_D1 6%).
- **COUNTER**: Phoenix loses to the mixture-with-reflection ablation on Stack_D1 (86 vs 90) and StackThree_D1 (20 vs 26) (Table 2).

### 2504.21432 v1 — UAV-VLN: end-to-end VLN for UAVs
- **OPERATION**: A fine-tuned TinyLlama-1.1B decomposes the instruction into sub-goals over a given discrete UAV action space. A task planner maps them to ROS 2 commands. Grounding DINO localizes the referenced objects. Termination needs detection + proximity + all sub-goals done.
- **INFO ACCESS**: TinyLlama is SFT'd on a >1,000-prompt UAV instruction/sub-plan set. The LLM sees text only; the detector sees the bottom camera.
- **CLUSTER**: UAV row → K104 weak.
- **WORKS**: SR 86.67/93.33/86.67/86.67 across 4 Gazebo scenes vs DEPS and VLMNav ≤86.67 (Table I). Ablation: Grounding DINO > ClipSeg > YOLO (YOLO 6.67–33.33) (Table II).
- **FAILS**: Only 15 episodes per scene, so one episode is 6.67 pts. No variance reported. Baselines are "adapted". No real flight. The planner/termination logic is described only in prose.
- **COUNTER**: Office SPL 0.795 < VLMNav 0.8667 (Table I). Untuned Gemini+Grounding-DINO matches or exceeds TinyLlama+Grounding-DINO (80/86.67/80/86.67 vs 73.33/80/80/80, Table II), so the fine-tune's margin is ≤1 episode per scene (inferred).

### 2504.21716 v1 — LLM-empowered embodied agent for memory-augmented household task planning
- **OPERATION**: A routing LLM classifies each request (action / history query / unclear). A planner LLM emits JSON pick-place targets from a VLM object list. A knowledge-base LLM answers history questions via RAG over timestamped Q-A chunks of past dialogue.
- **INFO ACCESS**: Frozen local LLMs (Qwen2.5-32B, Gemma2-27B, LLaMA3.1-8B); no training. Grounded SAM + LLaMA3.2-Vision supply object lists; retrieval is top-5 BGE-M3 chunks.
- **CLUSTER**: new **i: retrieval memory over interaction logs for user QA** (not control); K301 weak.
- **WORKS**: RAG raises KB validity, e.g. Qwen 53.75 → 91.3 (Table II). Planning strict accuracy 77.2 for Qwen (Table I). Routing 92.5 LLaMA (Table III).
- **FAILS**: 3 scenarios × 5 runs and 4 questions × 5 runs. Accuracy is offline plan/QA, with no executed success. The history is only 21 Q-A pairs (~4000 tokens) with injected errors. The authors note RAG struggles with repeated interactions (§V-D).
- **COUNTER**: LLaMA Trash Status drops with RAG (65 → 55) (Table II).

### 2505.03673 v2 — RoboOS: Brain-Cerebellum hierarchical framework for multi-agent collaboration
- **OPERATION**: A trained "brain" MLLM RAG-queries a shared scene-graph memory, emits a subtask DAG with robot assignments, and a monitor dispatches DAG levels in parallel. Per-subtask agents pick tools (VLA, grasp, nav) from a skill library with feedback-driven retry, and update spatial/temporal/robot memory.
- **INFO ACCESS**: RoboBrain-1.5-OS is Qwen2.5-VL-7B trained in 3 stages, ending with DeepSeek-V3-generated Multi-Robot-45k and Robotic-Agent-144k (error-injected negatives). Skills are frozen/pre-trained.
- **CLUSTER**: (c) (also b).
- **WORKS**: Multi-robot planning AR 81.74 vs DeepSeek-V3 76.21 and Qwen2.5-VL-7B 53.60. Affordance mAP 44.06 vs 27.10 (RoboBrain-1.0) (Table 1).
- **FAILS**: All numbers are offline benchmark accuracy on in-distribution synthetic data. The real world is qualitative demos only (§4.3). No end-to-end success, no ablation of shared memory, DAG scheduling or error correction. Limitations: three settings only.
- **COUNTER**: none.

### 2505.05622 v1 — CityNavAgent: aerial VLN with hierarchical semantic planning and global memory
- **OPERATION**: GPT-4V captions panoramas; Grounding DINO + SAM + depth build a 3D semantic point map. An LLM plans landmark sequence → object-of-interest → waypoint (mean of matching points). From any node of a topological graph of prior successful trajectories, LM-Nav-style graph search takes over.
- **INFO ACCESS**: Frozen GPT-4V/LLMs. Memory graph built from training-split trajectories in the same scenes, available at test (§5.1); successful trajectories only.
- **CLUSTER**: new **j: prior-trajectory topological route graph + graph search replacing online planning**; adjacent to K304.
- **WORKS**: AirVLN-E SR 28.3 vs LM-Nav 23.6 (Table 2). Removing the memory graph drops SR to 11.7 (Table 3).
- **FAILS**: AirVLN-S gain over best baseline only +1.3 / +0.9 SR (§5.2; Table 1 truncated). AirVLN-E is 101 self-built pairs. Memory graph is a training-route prior (inferred: privileged). Simulation only, no backtracking.
- **COUNTER**: The "w/o SM" ablation (23.6/19.2/119.4) is identical to the LM-Nav baseline row (Tables 2–3) (inferred: ablation = baseline). GPT-3.5 near GPT-4V on NE (98.9 vs 95.1).

### 2505.07236 v1 — UAV-CodeAgents: multi-agent ReAct UAV mission planning
- **OPERATION**: Run a smolagents CodeAgent "airspace manager" that calls VLM tools (describe image, pixel-point objects with JSON auto-repair) on a satellite image, orders waypoints by fire likelihood, and hands them to a UAV agent. - **INFO ACCESS**: Frozen Qwen2.5-72B (agents) and Qwen2.5VL-32B (vision). Separately, Qwen2.5VL-7B is SFT'd for pixel pointing on 9,000 satellite images. No 3D or embodied dynamics.

SFT grounding reports only mean distance/coverage per category with no reference model (Table III). The SFT model's use in the main runs is unclear (inferred).
- **COUNTER**: none.

### 2505.08765 v2 — CityAVOS / PRPSearcher: UAV visual object search in city space
- **OPERATION**: An MLLM picks target-related classes for Ground-SAM. Depth back-projection fills a 3D semantic grid. The MLLM scores each class's "attraction" into a cognitive map, with already-seen cells zeroed. A 3D uncertainty map decays with visibility. Map-derived exploitation advice, and exploration advice gated by threshold θ_T, are written into the action prompt (IPT).
- **INFO ACCESS**: Frozen MLLMs (GPT-4o, Qwen-vl-max, glm-4v-plus). Depth, pose and maps stay in the harness; the model gets only text advice.
- **CLUSTER**: (h) (fits h good).
- **WORKS**: Total SR 53.50 vs STMR 27.35. Without exploitation advice 10.41 (Table 2). Object-centric segmentation prompts 53.50 vs human-designed 38.46 (Table 3).
- **FAILS**: Uses 605 of 2,420 tasks (25%, API limits), single run, no variance. The θ_T grid was tuned on the same evaluation tasks (inferred). Hard-task SR 29.62 vs human 67.68.
- **COUNTER**: More advice hurts: advice every step (θ_T=0) SR 38.37 < none 49.19 (Table 4). Hard-task SPL is 16.65 with exploration vs 16.68 without (Table 2).
