## 第一阶段：只做校准

1. 汇报当前 corpus、模式卡和完整材料可用性；历史 screen/assignment 只是检索线索。
2. 按 SCORE_SPEC 预登记 6 篇开发 + 12 篇留出，以及类型/难度覆盖。保存选择理由；避免只挑流行/旧高分论文。
3. 每篇确认真实 ID/title/version，读取固定版本全文和附录。旧 fulltext 缓存可能截断：缺全文则 needs_fulltext，不输出分数。
4. 先写中心主张和证据表，再选匹配卡片，最后逐维判定。原文引用、位置、hash、解释和反证缺一不可。
5. 为七维补充 0/2/4 档实例。权重有问题可以提出有证据的修订，不能边看留出结果边调权。
6. 按 spec 做独立语义核对与留出校准；仅第二模型同意不能叫 gold。记录失败与争议，满足停止条件则停止批量。
7. 输出校准报告与冻结候选，不宣称科学有效性已获验证。安装 Open Scientist 并非运行此阶段的前提；需要修改领域卡/研究判据时才用它。

## 后续阶段（校准冻结后）

实现新的确定性 schema 校验与评分器：验证七维、版本/hash、引用位置、unknown/缺材料、总分和重复 ID；
测试未知项不能加分、代码 URL 不加分、权重和为 100、缺材料无总分、分歧不会静默覆盖。
通过后才按小批次重新评审，输出 research/v2/，保留实际模型 ID、session、输入/输出 hash。
不得复用 archive 内的旧 VERIFIED ledger、旧参考分或旧 Reel 文案作为结论。

本领域最关键的问题：模型通过哪一层 harness 控制什么本体，闭环成败如何判定，改进来自 harness、策略还是额外预算/特权信息？

每个阶段结束报告：实际读过什么、改变了什么、哪些检查通过、未解决什么、下一步。
不要自动安装插件、调用未授权的付费 API、跑训练、发布榜单或向 GitHub 推送。
